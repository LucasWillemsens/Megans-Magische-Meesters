Show hologram cards in a dedicated row above the lane cards so the board layout is clearer and holograms stand out, and add a flip hologram that shows a face-up preview when a lane card is flipped.

## Refined goal

Two kinds of holograms in the row above each lane:

### 1. Play-from-hand hologram (existing behavior, relocated)
When a card is dropped on a lane, the original card stays in the hand as a ghostly duplicate and a face-down hologram appears in the hologram row above the target lane. When either copy is hovered, a curved arrow appears from the hand card to the hologram and both copies come to the front. This way, even when the card is played face down, it can still be read in the hand. When the play executes, the flight animation fires from the hand.

### 2. Flip hologram (new)
When a face-down card on the lane is flipped (via click-to-flip), the lane card becomes ghostly (translucent, same as the hand ghost) and a face-up hologram appears in the hologram row above that lane. The face-up hologram shows the card art and is readable. A curved arrow connects the lane copy to the hologram copy (same arrow style as the play arrow). When either copy is hovered, the arrow appears and both copies come to the front.

## Implementation

### Template changes (viewBoard.jinja2)
- Add a `.hologramRow` `<ul>` inside each player lane `<li>`, above the existing `.cardRow`s
- Initially empty; holograms are created by JS when plays/flips are staged
- Player side only — enemy never has pending plays/flips

### JS changes (cardDragDrop.js)

#### Existing `onDropZoneDrop`
- Instead of removing the hand card (`this.draggedCard.remove()`), keep it in the hand and add CSS class `ghost` (translucent, pointer-events: none)
- The hologram `<div>` is appended to the correct lane's `.hologramRow` instead of inside the drop-zone
- On hover of either the hand ghost or the hologram, show a curved arrow connecting them
- When play executes (POST), the flight animation removes the ghost from the hand

#### New flip hologram in `onFaceDownCardClick`
- After flipping the lane card face-up:
  - Add CSS class `ghost` to the lane card (translucent, still face-up with art visible)
  - Create a face-up hologram clone in the lane's `.hologramRow` 
  - The face-up hologram shows the art and info (same as a face-up card)
  - Add click-to-flip listener to the hologram (same as today's one-shot flip)
  - On hover of either, curved arrow connects lane card to hologram

#### Curved arrow
- An SVG or CSS curved arrow between the two cards, positioned absolutely
- Visible only on hover of either the source or hologram card
- Arrow direction: curved path indicating "this card is previewed above/below"
- Same arrow style for both play and flip holograms

#### Ghost style
- CSS class `.ghost`: `opacity: 0.4; filter: grayscale(0.3); pointer-events: none;`
- The source card (hand or lane) gets `.ghost`, the hologram gets `.hologram` (existing class)
- Hovering the hologram triggers both the arrow AND brings both copies to front

### Keep existing behavior
- One-shot click-to-flip on the hologram still works
- The flight animation from the hand still fires on play execution
- Drop-zone stays in the lane (not the hologram row)
- Enemy never has holograms

## Acceptance criteria
- [ ] Dropping a card on a lane leaves a ghost copy in the hand and creates a face-down hologram in the hologram row
- [ ] Flipping a lane card creates a face-up hologram in the hologram row and marks the lane card as ghost
- [ ] Curved arrow connects source card ↔ hologram on hover of either
- [ ] Hovering brings both copies to front (z-index)
- [ ] Ghost cards have reduced opacity and no pointer events
- [ ] Click-to-flip works on holograms
- [ ] Flight animation still originates from the hand ghost
- [ ] Enemy has no hologram rows

- `lane-card-stacking` may affect layout but is not a hard dependency

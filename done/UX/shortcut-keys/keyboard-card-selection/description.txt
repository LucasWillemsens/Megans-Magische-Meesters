Select an eligible hand card by keyboard and show a face-up lane preview without staging a cookie.

Implementation:
1. Extend `CardDragDropSystem` in `var/www/static/cardDragDrop.js` with a keyboard-selection state containing the selected `li.cardContainer`, card id, source lane/ordinal, current lane value, hologram element, and digit buffer. Initialize it only on a player board and clear it on cancellation, confirmation, phase/loading changes, and board teardown.
2. Enumerate eligible cards in DOM order across every final `ul.hand`/hand fan. Require a player-owned `li.cardContainer` with its hidden `input[name="card_id"]`; skip `.blocked`, `.ghost`, already-staged/non-draggable cards, `.loading`, and enemy-board cards. The numeric index is therefore the playable-card index, not an index that can select an exhausted card.
3. Implement the documented no-zero parser: 1–9 select the corresponding eligible card immediately; a multi-digit buffer is valid only when every typed digit is 1–9, and maps to the ordinal among positive decimal strings containing no zero (`11` → card 10, `12` → card 11, `19` → card 18, `21` → card 19). Pressing `0` clears the buffer and cancels the current preview. Invalid/out-of-range buffers do not select a card and must not throw or submit.
4. Build a keyboard preview in the selected card's own lane (`cardType + 1`) under that lane's `.hologramRow`. Reuse/refactor the existing clone-building path from `onDropZoneDrop()`, but make this preview face-up, remove forms/buttons/hidden controls, mark it with a dedicated `.keyboard-preview`/data attribute, and never call `createupdateCookie()` or attach `onFaceDownCardClick()` during selection.
5. Mark the source card with a selected/ghost-like visual class and add CSS in `var/www/static/cardDragDrop.css` or `cards.css`. Selecting another eligible card must remove the old preview/class before creating the new one; selecting with no hand cards or while any board card/timeline is loading is a no-op.
6. Add browser-level checks for direct digits, 10+ no-zero sequences, blocked-card skipping, empty hands, static/image cards, input focus, enemy phase, multi-fan DOM order, and the invariant that `document.cookie` is unchanged until confirmation.

Files to create/modify:
- `var/www/static/cardDragDrop.js` — keyboard listener/parser, eligible-card enumeration, preview lifecycle, and selection cleanup.
- `var/www/static/cardDragDrop.css` or `var/www/static/cards.css` — selected source and face-up keyboard-preview styles.
- `MMM/jinja2/MMM/battle/viewBoard.jinja2` — only if a stable `data-card-id`/source hook is needed; preserve hidden `card_id`, `data-source-lane`, and `data-source-ordinal`.
- `MMM/tests.py` — stable rendered-hook/turn-phase regressions; use a real DOM/browser test for key events and cookie absence.

Acceptance criteria:
- [ ] Pressing 1–9 selects the corresponding eligible hand card and previews it in its card-type lane.
- [ ] `11` selects eligible card 10, `12` selects eligible card 11, and no sequence containing 0 is treated as a position; 0 resets/cancels.
- [ ] Blocked, ghosted, staged, loading, enemy, and absent cards cannot be selected.
- [ ] The preview is face-up, rotated/styled like a hologram, and has no face-down click listener.
- [ ] Selecting another card/cancelling removes the previous preview and restores the source card.
- [ ] Selection alone writes no cookie, changes no server state, and does not change staged play/flip counts.
- [ ] Shortcuts are inactive in form text controls, enemy phase, and loading/timeline phases.

Dependencies:
- `done/battle-interaction/drag-drop-to-lane/` and `done/battle-interaction/hologram-previews/` — clone/drop-zone/hologram conventions.
- `done/turn-affordances/staged-action-blocking/` — `.blocked`, staged-card, and allowance guards.
- `roadmap/UX/consistent-styling/large-hand-rendering/` — final multi-fan DOM/order must be stable first.
- `confirm-and-navigate/` depends on the selection state and preview lifecycle defined here.

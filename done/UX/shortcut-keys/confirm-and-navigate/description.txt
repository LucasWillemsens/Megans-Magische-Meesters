Confirm, move, or cancel a keyboard-selected card while preserving drag/drop cookie semantics.

Implementation:
1. Extend the selection handler in `var/www/static/cardDragDrop.js` so Space and Enter act only when a keyboard preview is active (and do not steal native form behavior otherwise). Re-check the selected card's `.blocked`/`.ghost`/loading state and `remainingAllowances().plays` at the moment of confirmation.
2. On confirmation, call the existing `createupdateCookie(cardId, laneValue, false, sourceLane, sourceOrdinal)` exactly once. Reuse its JSON payload/path; do not add a keyboard-specific cookie writer or submit the form immediately. Add the same `.ghost`, `draggable="false"`, `this.staged.plays++`, and `applyTurnAffordances()` effects as `onDropZoneDrop()`.
3. Use the four `dropZones` owned by `CardDragDropSystem` for arrow navigation. Left/right/up/down should move one lane with wrap-around `1 → 2 → 3 → 4 → 1`; remove/rebuild the preview in the new lane's `.hologramRow`, update the stored lane value, preserve the card rotation, and prevent page scrolling.
4. Add a click listener to each `.drop-zone` that confirms an active keyboard selection into the clicked zone's lane. The clicked lane wins over the preview lane. Do not interfere with ordinary drag/drop events when no keyboard selection is active.
5. Escape and 0 must remove the keyboard preview, remove only the unconfirmed selection class, clear the card/buffer/lane state, and leave no cookie or staged counter. A confirmed keyboard play becomes a normal pending play/ghost state and must not be accidentally confirmed a second time; the keyboard preview clone must never receive a face-down flip listener.
6. Verify the exact cookie string/payload against `onDropZoneDrop()` and test Space/Enter, all arrow directions/wrap, drop-zone click, Escape/0, mid-selection budget exhaustion, repeated confirmation, and browser focus behavior.

Files to create/modify:
- `var/www/static/cardDragDrop.js` — confirmation/navigation/cancellation handlers and drop-zone click integration.
- `var/www/static/cardDragDrop.css` or `var/www/static/cards.css` — selected/confirmed ghost and lane-preview state if the first leaf did not cover it.
- `MMM/tests.py` — no-cookie/server-action regression if a stable hook is added; browser/DOM tests for actual key/click events.

Acceptance criteria:
- [ ] Space/Enter writes exactly the existing play-cookie payload for the selected lane and leaves the hand card as the normal staged ghost.
- [ ] Arrow keys move the preview through all four lanes with wrap-around and no page scroll.
- [ ] Clicking a drop zone confirms to that zone, regardless of the preview's previous lane.
- [ ] Escape/0 removes the preview and selection without a cookie or staged-count change.
- [ ] Confirmation is refused when allowances or card eligibility are exhausted at confirm time.
- [ ] A keyboard-created preview is never treated as a click-to-flip hologram, and repeated confirmation cannot duplicate the play.
- [ ] Drag/drop and click-to-flip behavior remain unchanged for non-keyboard interactions.

## Consistent styling (8/8 complete)

Battle, player, and challenge-page presentation made consistent without changing game rules.

1. `in-game-cursor-affordances` — Non-blocked player face-down lane cards and face-down holograms get `cursor: pointer`; blocked cards keep `cursor: not-allowed`; enemy boards never acquire pointer cursors; the drawable top deck card tilts on hover only when the draw button is enabled and the deck is non-empty (`cardDragDrop.css`, `cards.css`).
2. `hand-card-visibility` — The bottom-anchored card-type footer cascade was restored (7px / -2.75rem base rule, 0.65rem static-card override); static cards show a type-only footer with no centered suit overlay; the enemy hand renders as a horizontal scrollable flex row instead of a clipped vertical stack (`cards.css`).
3. `lane-ordinal-on-play` — `BattleParticipant.playCard()` computes the destination lane maximum BEFORE moving the card so a stale hand ordinal can never inflate it; the direct trusted starting-card play initializes to ordinal 1; empty lanes start at 1; covered for human, bot, special, empty-lane, occupied-lane, and trusted-lane cases (`MMM/models.py`, `MMM/tests.py`).
4. `large-deck-rendering` — `contextBoard()`/`newBoard()` partition decks into a rightmost active stack of at most 32 cards plus inert 32-card indicator chips (`DECK_BLOCK_SIZE = 32`, `_deck_presentation()`); the board template renders `.deck-stack`/`ul.deck-indicator` wrappers with `aria-hidden inert` chips and a single `.active-deck` draw form; `loadingAnimations.js` targets the active deck explicitly; rendering tests cover 32/40/64/65-card decks (`MMM/views.py`, `viewBoard.jinja2`, `cards.css`).
5. `large-hand-rendering` — The player hand renders as rotating fans inside a `.hand-scroll` wrapper (server-chunked `handFans`, one `.hand-fan` `<ul>` per chunk with `data-fan-index`); per-fan rotation patterns, responsive horizontal scrolling, and fan-aware drag/drop + animation source lookup (`MMM/views.py`, `viewBoard.jinja2`, `cards.css`, `cardDragDrop.js`, `loadingAnimations.js`). Fan size later reduced 13 → 9 by `board-interaction-fixes/keyboard-selection-extensions`.
6. `player-page-polish` — Possessive fix (`Lucas' page` vs `Meg's page`), challenge cards rewritten as valid semantic markup with a single block-level `.challenge-card-link`, no nested anchors, and `draggable="false"`; compact responsive styles in `style.css` (`viewPlayer.jinja2`).
7. `owned-cards-sorting` — `viewPlayer()` accepts `?sort=name|type|date` and passes an explicitly sorted `ownedCards` list built from `Player.getCollection()` (so a card whose latest owner is another player never shows); name sorts case-insensitively by title, type by cardType 0–3, date by the player's latest `CardOwnerHistory.aquiredAt` newest-first; sort controls are plain links with active/ARIA state, no JavaScript required (`MMM/views.py`, `viewPlayer.jinja2`, `style.css`).
8. `challenge-page-default-selection` — `createGame.jinja2` radio markup repaired (void `<input>`, no `</input>` closing tags) and the first valid player, deck, and starting card are preselected with `loop.first` checked; the "New deck" fallback is checked when no saved decks exist; form fields, names, and CSRF unchanged.

## Shortcut keys (4/4 complete)

Accessible keyboard controls that reuse the existing cookie-staged action system; all shortcuts are inactive in text controls, enemy/loading/timeline phases, and for exhausted or blocked actions.

1. `keyboard-card-selection` — Digits 1–9 select the corresponding eligible hand card via the no-zero parser (11 → card 10, 21 → card 19, ...); the selection builds a face-up `.keyboard-preview` hologram in the card's own lane and writes NO cookie; blocked/ghost/staged/loading/enemy cards are excluded (`cardDragDrop.js`).
2. `confirm-and-navigate` — Space/Enter confirms via the exact drag/drop `createupdateCookie()` payload; arrow keys move the preview across the four lanes with wrap-around; drop-zone clicks confirm into the clicked lane; Escape/0 (and Backspace) cancel without cookie or staged-count change (`cardDragDrop.js`).
3. `hold-to-end-turn` — Holding **e** for one continuous second submits the existing end-turn form exactly once; early release, repeat keys, blur, and visibility changes cancel cleanly; `.shortcut-hold-loading` shows a visible one-second progress bar with `aria-busy` and a reduced-motion fallback (`cardDragDrop.js`, `cardDragDrop.css`).
4. `hold-to-draw` — Holding **d** for one second draws via the existing active-deck draw form; same shared `ShortcutHoldAction` helper, progress indicator, guards (non-blocked active deck, draws remaining, player phase), and single-submission guarantees.

3. `handcard-action-merge` — The per-handcard play form/button was removed; cards keep bare hidden `card_id` and `lane` inputs as JS contracts; playable cards carry `tabindex="-1"` (later `0` per board-qa-followups); number-key and click selection both focus the selected card; the orange selection styling was unified with the regular focus ring (no glow) (`viewBoard.jinja2`, `cardDragDrop.js`, `cardDragDrop.css`).
4. `keyboard-selection-extensions` — Hand fans shrunk from 13 to 9 cards (`HAND_FAN_SIZE = 9` in `views.py` and `loadingAnimations.js`, fan width `calc(8.8em + 5.25rem)`, dead nth-child/rotation rows pruned); `+`/`-` step through eligible cards with wrap-around; Backspace cancels like 0 (with `preventDefault`); oversized buffers fall back to the last digit; confirming a selection stages the same faceDown hologram as drag-and-drop plays with rotation continuity, one-shot click-to-flip, and `tabindex="0"` only while flips remain.

6. `deck-stable-draw` — `duplicateCard()` negative-lane clones are no longer inserted into the deck `<ul>`; the clone is positioned fixed at the deck top-card rect and appended to `document.body`, so nth-child offsets never shift; `--move-x`/`--move-y` measured after fixed positioning keeps the `.to-original` flight + transitionend reveal unchanged; a contract test pins the no-insert behavior (`loadingAnimations.js`, `MMM/tests.py`).
7. `compact-active-challenges` — `viewPlayer()` replaces the N+1 challenge loop with a single prefetched `BattleHistory` queryset mapped to enriched dicts (participants, loot text, game, started, finished/won/fled via a pure `_challenge_result_for_player` helper, boardUrl/gameUrl); the template renders compact inline challenge rows with a Won/Lost/Fled badge on finished games and links own games straight to `/game/<id>/board/<player>/`; `style.css` compacts the block and adds badge variants; tests pin board URLs, badge absence on active games, and the finished-game badge.

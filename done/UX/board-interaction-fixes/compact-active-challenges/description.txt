Make the active challenges list on the player page take less vertical space, show the
result when a game is over, and link own games straight to the board (the board redirects
to the result page when finished).

Subgoals (land in this order):
1. `view-challenge-enrichment/` — replace the plain BattleHistory list in
   `viewPlayer()` with enriched dicts `{history, game, participants, isParticipant,
   finished, won, boardUrl, gameUrl, started}` using one prefetched queryset.
2. `compact-template-board-links/` — compact single-link rows in `viewPlayer.jinja2`;
   result badge for finished games; boardUrl for own games, gameUrl otherwise.
3. `compact-styles-and-tests/` — compact `.challenge-list`/`.challenge-card` styles +
   result badge styles in `style.css`; update the three affected test cases.

Key codebase facts (verified):
- `MMM/views.py viewPlayer()` builds `challenges` by looping
  `BattleParticipant.objects.filter(player_id=...)` then `battle.player.challenges.all()`
  (BattleHistory where challenger == viewing player) — N+1 heavy, deduped with
  `list(set(...))`.
- `viewPlayer.jinja2` renders each challenge as a large `.challenge-card`; the single link
  goes to `{{returnURL}}game/{{challenge.game.get().id}}/{{player.id}}` (game page).
- `Game.history` reverse relation is named `game` (a related manager → use
  `.first()`/`.all()`), `BattleHistory.participants` is a M2M to BattleParticipant,
  `_game_result(game)` returns `(finished, win, active_participants)` where
  active_participants are the non-defeated/non-fled participants when finished.
- Board URL pattern: `game/<int:game_id>/board/<int:player_id>/` (`urls.py`);
  `viewBoard` redirects to `/game/<id>/result/<player_id>/` when finished (non-sequence
  requests), so linking straight to the board is safe for active AND finished own games.
- Tests to touch live in `PlayerPageTests`:
  `test_challenge_card_is_one_keyboard_link_with_valid_metadata_markup`,
  `test_player_page_keeps_empty_challenge_participant_state`,
  `test_challenge_card_styles_cover_stacking_hover_and_focus`.

Acceptance criteria (leaf-level, detailed per subgoal):
- [ ] Challenge list takes visibly less vertical space per row.
- [ ] Finished games show Won/Lost/Fled in the row preview.
- [ ] Clicking an own challenge loads the board directly (result redirect for finished).
- [ ] Pending/no-participant challenges still show "No participants" and link to the game
      page.
- [ ] Rows remain ONE keyboard-navigable link each with valid hover/focus styles.
- [ ] Query count drops vs the current N+1 loop (prefetch participants/game/loot).

Dependencies:
- independent of the board leaves; planned last in this goal to avoid test churn on
  shared suites.

Keep the affordances truthful while the player stages cookie plays/flips client-side: `cardDragDrop.js` tracks staged plays/flips against the `#turnLimits` budgets (same formulas), blocks the hand/lane cards/deck the moment a budget runs out mid-turn, and refuses new drags/flips once blocked.

## Prerequisites

This leaf depends on both `turn-allowance-backend` (the `#turnLimits` data contract) and `blocked-board-visuals` (the CSS classes and blocked element structure).

## Implementation

### 1. cardDragDrop.js — Constructor/init

Read `#turnLimits` dataset into:

```javascript
this.turnAllowances = {
    int: parseInt(dataset.intCount),
    spd: parseInt(dataset.spdCount),
    tactics: parseInt(dataset.tactics),
    drawn: parseInt(dataset.drawn),
    played: parseInt(dataset.played),
    flipped: parseInt(dataset.flipped),
};
this.staged = { plays: 0, flips: 0 };
this.tooltips = {
    draw: dataset.drawBlockedTitle,
    play: dataset.playBlockedTitle,
    flip: dataset.flipBlockedTitle,
};
```

### 2. remainingAllowances() — JS mirror of the three formulas

```javascript
remainingAllowances() {
    const { int, spd, tactics, drawn, played, flipped } = this.turnAllowances;
    const { plays: stagedPlays, flips: stagedFlips } = this.staged;
    const effectivePlayed = played + stagedPlays;
    const effectiveFlipped = flipped + stagedFlips;
    return {
        draws: Math.max(0, int + 1 + Math.min(0, spd + 1 - effectiveFlipped - effectivePlayed) - drawn),
        flips: Math.max(0, spd + 1 + Math.min(0, int + 1 - drawn - effectivePlayed) - effectiveFlipped),
        plays: Math.max(0, 2 + tactics - drawn - effectiveFlipped - effectivePlayed),
    };
}
```

### 3. applyTurnAffordances()

- `plays <= 0` → all hand `li.cardContainer:not(.blocked)`: add `.blocked`, `draggable="false"`, title=play tooltip.
- `flips <= 0` → all `.playerBoard .cardContainer.faceDown:not(.blocked)` + pending `.hologram .cardContainer.faceDown`: add `.blocked`, title=flip tooltip.
- `draws <= 0` → `ul.deck`: add `.blocked`; `button.draw` disabled.

### 4. Hooks

- **`onDropZoneDrop`**: increment `this.staged.plays++` then recompute + apply via `applyTurnAffordances()`.
- **`onFaceDownCardClick`**: guard — if `remaining().flips <= 0` return early; else `staged.flips++` then recompute + apply (covers hologram flips — same handler).
- **`onCardDragStart`**: if `remaining().plays <= 0` → `preventDefault()` / return (covers cards bound before budget ran out).

### 5. Init

Call `applyTurnAffordances()` once after `setupFaceDownCardClickListeners()` (no-op on fresh boards where all budgets are positive).

### 6. Monotonic note

Staged counts never decrease (no un-staging today). The future undo-button goal (README bullet under battle-page-polish, not yet planned) must decrement staged counts and re-run `applyTurnAffordances` on undo.

### 7. Interaction with hologram-row

Hologram-row (sibling goal, unscheduled) changes drop behavior (hand card stays as ghost). If it lands first, apply the hand-blocking to the ghost copy too. If this lands first, hologram-row must keep the `.blocked` class on the ghost copy.

### 8. Tests

- **Staged plays block remaining hand**: Board with budget for 1 play → stage one play via drop → remaining hand cards get `.blocked` and `draggable="false"` immediately (no POST).
- **Staged flips block remaining lane cards**: Board with budget for 1 flip → click one face-down card → remaining face-down cards get `.blocked` and click is no-op.
- **Over-playing shrinks draw budget**: With low int+spd, staging a play reduces `draws_left` via the min clause; verify `ul.deck` shows `.blocked` when it hits 0.
- **Fresh board**: No blocking applied; existing drag/click behavior unchanged.

## Acceptance criteria

- [ ] Staging plays up to the limit greys the remaining hand cards immediately (no POST needed)
- [ ] Staging flips up to the limit greys remaining face-down lane cards and pending holograms immediately
- [ ] Over-playing past the Speed+1 slack greys the deck (draws_left shrinks via min clause)
- [ ] Blocked elements can't be dragged/clicked; `cursor: not-allowed`; tooltips match the server-rendered strings
- [ ] Fresh board + full budget → no visual change; `python3 manage.py test` stays green (data contract untouched)

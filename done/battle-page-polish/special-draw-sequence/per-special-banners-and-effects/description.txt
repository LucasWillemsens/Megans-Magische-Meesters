Implement per-special vignette animations: banner display with the existing sentence-style messages from views.py print statements, lane highlighting for the winning stat, and card-specific visual effects (flight, flip, trust glow, attack flash). Each special kind (int, spd, vis, res) gets its own look and feel while sharing the common sequencer infrastructure.

## Implementation

### 2. Lane highlighting: WHY first, WHAT second

**Trigger step (WHY):** The lane matching the special's stat glows:
- intSpecial → lane 1 (Intelligence) — "Intelligence caused this"
- spdSpecial → lane 2 (Speed)
- visSpecial → lane 3 (Viciousness)  
- resSpecial → lane 4 (Resolve)

The revealed (face-up) cards in that lane get a glow effect. This tells the player "this stat's cards triggered the special."

Implementation: In `playStep()` for `special-trigger`, call `highlightLane(participantId, lane)` which:
1. Finds the participant's board (own or enemy)
2. Adds CSS class `.lane-highlight` to the `.lane.{LaneName}` element
3. Adds CSS class `.card-highlight` to each face-up card in that lane
4. Removes after the step's duration

**Effect steps (WHAT):** On `card-effect` steps, the lanes where cards land glow:
- If a card-effect step moves cards to lane 3, lane 3 glows (the destination)
- This tells the player "these cards are being affected"

### 3. Per-special card effects

**intSpecial — Master Plan (cards fly hand→lane, flip face-up):**
- `card-effect` steps: each hand card gets a duplicate flying from hand (sourceLane=0) to its target lane
- The duplicate shows the card back in flight, then flips face-up on landing
- Use existing `duplicateCard()` with negative source lane NOT needed (they start in hand, not deck)
- After landing, card appears face-up in the lane (it was already flipped by playCard during server execution)
- The template already renders the card in its final state; the duplicate flies from the hand slot to the lane slot

**resSpecial — Trust (cards gain trust glow):**
- `card-effect` steps: each trusted card glows
- No flight animation (cards stay in place)
- Instead: add CSS class `.trust-glow` which adds a golden/pulse border effect
- The glow is a CSS animation: golden border, slight scale pulse, shadow
- After the step duration, the glow remains (the card is now trusted permanently)
- The existing template already shows trusted cards in a `.trustedCards` row — the glow makes the transition visible

**visSpecial — Attack (flash, resolve lock, defeat dim):**
- Trigger step: board flash effect on the target opponent board
  - `.board-flash` CSS class: brief white flash overlay that fades
- `card-effect` step: the trusted resolve card gets a trust glow (same as resSpecial glow)
- `participant-effect` step: if opponent defeated, opponent's board gets `.board-dimmed` (permanent, game over)
- If self-defeated (drain), the player's own board gets `.board-dimmed`

**spdSpecial — Rush / Flee:**
- Trigger step: Speed lane highlights
- If rush down: no card-effect for the rusher (the opponent's subsequent special steps handle their own effects)
- If flee: `participant-effect` step dims the fleeing player's board (they fled, board still visible but greyed)
- Flee step also shows the stealing animation: one enemy card flies to the fleeing player's side (stealing). The card that is stolen is determined server-side but the visual just needs a card flying from enemy board to player side. For MVP, skip the steal visual and just show the flee banner + dim.

**Common banner styling:**
The banner from `turnMarker()` needs enhancement:
- Banner appears at top-center (not center-screen) so the board is still visible
- Banner shows the full sentence text
- `special-trigger` banners hold longer (2-3 seconds) so the player can read
- `participant-effect` banners hold 2-3 seconds

Create a new function `showBanner(text, holdMs, variant)` that:
- Positions at top third of screen
- Has a distinct style depending on variant (special-trigger = gold border, participant-effect = red/green)
- Hold duration based on text length (at least 2s, longer for long sentences)

### 4. CSS additions needed

Add to `var/www/static/cards.css`:

```css
/* Lane highlight - glow effect */
.lane-highlight {
    box-shadow: inset 0 0 20px rgba(255, 215, 0, 0.5);
    border-color: gold;
    transition: box-shadow 0.3s ease;
}

/* Individual card highlight in triggered lane */
.card-highlight {
    box-shadow: 0 0 10px rgba(255, 215, 0, 0.7);
    filter: brightness(1.2);
    transition: all 0.3s ease;
}

/* Trust glow - pulsing gold */
.trust-glow {
    animation: trustPulse 1.5s ease-in-out 3;
    border-color: gold !important;
    box-shadow: 0 0 15px rgba(255, 215, 0, 0.6);
}

@keyframes trustPulse {
    0%, 100% { box-shadow: 0 0 15px rgba(255, 215, 0, 0.6); }
    50% { box-shadow: 0 0 25px rgba(255, 215, 0, 0.9); }
}

/* Board dim for defeat/flee */
.board-dimmed {
    opacity: 0.5;
    filter: grayscale(0.6);
    pointer-events: none;
    transition: all 0.5s ease;
}

/* Board flash on vis attack */
.board-flash {
    animation: attackFlash 0.5s ease-out;
}

@keyframes attackFlash {
    0% { background-color: rgba(255, 255, 255, 0.6); }
    100% { background-color: transparent; }
}

/* Banner variant styles */
.banner-special { border-color: gold; background: linear-gradient(135deg, #2a1a00, #4a3000); }
.banner-defeat { border-color: #ff4444; background: linear-gradient(135deg, #2a0000, #4a0000); }
.banner-flee { border-color: #888; background: linear-gradient(135deg, #1a1a2a, #2a2a3a); }
```

### 5. Template: lane highlighting hooks

The template needs to support lane highlighting by ID. Each `.lane` element should have a predictable selector. Currently they render as `<li class="lane {{lane.name}}">`. The JS can select them with `.playerBoard .lane.Intelligence` etc. For enemy lanes, use `.enemyBoard .lane.Intelligence`.

No template changes needed for lane highlighting beyond what exists — the CSS class name is the lane name.

### 6. Banner for enemy-side specials

When a timeline step targets an enemy participant (different `participantId`), the banner and highlighting should appear on the enemy's board area:
- Banner still shows the player's name (e.g., "Bot enacts master plan")
- Lane highlight on the enemy's lanes
- dim on the enemy's board

The JS sequencer already has access to `step.participantId` and can determine which board to target using the existing `.enemyBoard` selectors and the participant's name.

Render a full-screen veil over the board on action-URL renders so the final board state is unreadable while the loading animations play above it; lift the veil only when the page will not navigate away.

Implementation:
1. Server signal: in MMM/views.py viewBoard(), add "obfuscateBoard" to the context dict (views.py:232-249), True exactly when the render comes from boardAction(). boardAction() is the only caller that passes an explicit turn_phase argument ("" for draw/unknown actions, "playerMoves" for end_turn - views.py:305-312), while the /board/<pid>/ URL route passes none, so action_render = turn_phase is not None inside viewBoard() is the reliable signal. Do not derive it from request.path: keeping it an explicit render-mode flag makes it unit-testable and independent of URL formatting.
2. Template: in MMM/jinja2/MMM/battle/viewBoard.jinja2, right after the #turnPhase block (lines 4-9):
       {% if obfuscateBoard %}<div id="boardVeil" class="boardVeil" aria-hidden="true"></div>{% endif %}
   Do NOT fold this into the #turnPhase div: #turnPhase must stay conditionally rendered (tests assert a clean board contains no data-phase= attribute) and the veil is independent of the turn phase.
3. CSS: in var/www/static/cards.css, next to the .duplicate rules (~line 1264):
       /* action-URL veil: obfuscates the final board state while the loading
          animations play above it (duplicates z-999, turn markers z-1000);
          loadingAnimations.js lifts it only when no navigation follows */
       .boardVeil {
           position: fixed;
           inset: 0;
           z-index: 500;
           background: rgba(12, 12, 24, 0.7);
           backdrop-filter: blur(5px);
           transition: opacity 0.35s ease-in-out;
       }
       .boardVeil.lifted {
           opacity: 0;
           pointer-events: none;
       }
   Keep pointer-events enabled while the veil is visible: it double-duties as a click shield during the animation window (complements roadmap/tests-and-reliability/duplicate-submit-prevention). z-index 500 sits above the board chrome (.playerScreen/.deckHand z-1) but below .duplicate (z-999) and .enemyTurnMarker (z-1000), so the flying cards and turn markers stay fully visible above the veil.
4. JS lifecycle in var/www/static/loadingAnimations.js Animate():
   - const veil = document.getElementById('boardVeil'); and a liftVeil() helper that adds 'lifted' and removes the node after the opacity transition (transitionend plus a ~400ms setTimeout fallback).
   - Branches that schedule reloadToBoard (phase 'playerMoves' lines 94-105, phase 'enemy' lines 108-144, default-with-elements lines 146-173): leave the veil in place - the page navigates away and the reload renders the clean board.
   - phase === 'player' branch (lines 79-92, never reloads): liftVeil() defensively (the veil should never render there, since that phase only renders on the board URL).
   - The zero-element else branch (lines 174-176, e.g. an action POST that produced an error message and nothing to animate): liftVeil() so the board and the error message become readable, and keep the current no-reload behaviour so error messages are not lost.
   Never leave the veil up on a render that stays on screen.

When a lane card is hovered, bring it fully into view before any card that overlaps it — matching the behavior of hand cards. Cards with lower ordinal (behind the hovered card) stay hidden underneath; cards above (higher ordinal) are pushed aside or visually appear behind the hovered card.

The hand-card hover behavior uses `bottom: 1em` and `z-index` changes. For lane cards, the approach must work with the absolute-positioned overlapping layout: on hover, the card slides up/forward so its full face is visible, and its z-index rises above all siblings.

## Implementation

### 1. CSS hover rules (cards.css)

Add hover rules for `li.cardContainer` inside `.cardRow`:

```css
/* Lane card hover — come fully into view */
.playingCards ul.cardRow li.cardContainer:not(.blocked):hover {
    z-index: 100;                          /* Above all other lane cards */
    transform: translateY(-1.5em) rotate(var(--card-rotation, 0deg));
    /* Translate Y lifts the card above overlapping cards */
    /* Keep the random rotation during hover for consistency */
    filter: drop-shadow(0.2em 0.2em 0.3em rgba(0,0,0,0.4));
    transition: transform 0.15s ease-out, filter 0.15s ease-out, z-index 0s;
}
```

- The `translateY(-1.5em)` lifts the card up so its full face is visible above the overlapping cards in front of it
- The `z-index: 100` ensures it's above all other cards in the row
- Cards that it was previously behind (lower ordinal) remain hidden — the translate moves it out from under them
- Cards that were on top of it (higher ordinal) now appear behind it due to z-index

For face-down cards:
```css
.playingCards ul.cardRow li.cardContainer.faceDown:not(.blocked):hover {
    z-index: 100;
    transform: translateY(-1.5em);
    /* Face-down cards don't show art, but still need to lift */
}
```

### 2. Hover for overlapping card rows

For multi-row scenarios (subgoal 2):
- Hovered card in an overflow row lifts similarly
- Ensure z-index spans across rows (use a high enough value like 100 or 1000)
- Cards in different rows don't overlap each other, so no cross-row z-index conflicts

### 3. Hover on trusted cards row

Apply the same hover behavior to cards in the `trustedCards` `.cardRow`.

### 4. Prevent hover interference with drag-and-drop

- Cards being dragged should not trigger hover (the `.dragging` class already prevents interaction)
- Ghost cards (`.ghost` class) should not respond to hover (they have `pointer-events: none`)
- Blocked cards (`.blocked` class) already have their own hover styling — don't override

### 5. Focus-within parity

Add `:focus-within` rules for keyboard accessibility, matching the hover transform:
```css
.playingCards ul.cardRow li.cardContainer:not(.blocked):focus-within {
    z-index: 100;
    transform: translateY(-1.5em) rotate(var(--card-rotation, 0deg));
}
```

### 6. Hover on face-down lane cards showing art

When a face-down card is hovered (before flipping), the card back is shown. The lift behavior should still apply. No special art preview is needed here — the flip hologram (already implemented in hologram-row) handles showing art.

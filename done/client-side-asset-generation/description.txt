Allow usage of efficient client computed assets. These can be especially useful for testing or as a fallback when asset loading fails.

The first subgoal is: New cards should be able to use the card look of the cards.css default deck of cards. The symbols of the regular deck of cards should map thusly: Spades -> Speed. Diamonds -> Viciousness. Hearts -> Resolve. Clubs -> Intelligence (the 4th suit for the 4th type). The numbers or faces on a card do not matter for gameplay purposes but should uniquely identify the cards as a replacement of what would otherwise be the art and the name. Give a default name to the regular cards like: jack of spades or three of clubs

## Subgoals

1. **suit-rank-helpers** — Jinja2 filter functions that compute a playing card rank class, rank display letter, suit class, and suit symbol from a Card model instance. Also a function to generate a default name (e.g. "Jack of Spades"). All go into `mysite/jinja2.py`.

2. **template-updates** — Update all templates that render cards (index.jinja2, viewCard.jinja2, viewPlayer.jinja2, createGame.jinja2, viewBoard.jinja2) to render CSS playing card markup (rank class, suit class, rank span, suit span) instead of the fallback image `1flubeltje.jpg` when `artSource == ""`.

3. **css-adjustments** — Add CSS rules so the playing card rendering fits within the existing `.smallCard` layout alongside `.smallCardInfo` without overlap or broken sizing.

## Dependency order

suit-rank-helpers → template-updates → css-adjustments

(Each subgoal must be completed before the next begins, though css-adjustments can be partially done in parallel with template-updates for testing.)

Deploy each eligible same-repository PR branch to `https://pr-<number>.paintedpillars.com/`. Objective/end-to-end test: push a same-repository PR and verify isolated test/deployment readiness and PR link; verify a fork PR is never executed on the host.

Implementation:
1. Add a loop-owned deployment manager and configuration/documentation under `scripts/` (no GitHub runner). Validate PR head repository identity against the configured canonical repository before checkout or any code execution; serialize builds; rebuild on each push.
2. Create a separate checkout, runtime port, and SQLite database per PR. Parameterize `mysite/settings.py` deployment values (secret key, debug, allowed hosts/origins, secure cookies, database path) through environment variables while retaining local development defaults. Add pinned runtime dependencies in a repository dependency file only if needed; `requirements.txt` does not currently exist. Never access the Windows-hosted production checkout/database.
3. For each build, migrate and seed the isolated database deterministically, then run `manage.py check` and `manage.py test`; publish ready state only on success and record failures without a playable-ready status. Use the repository's existing test suite in `MMM/tests.py`; add deployment-manager focused tests there or in a new `scripts/` test module.
4. Route `pr-<number>.paintedpillars.com` to the environment's local port through one reverse proxy and Cloudflare Tunnel wildcard forwarding, with no per-PR tunnel changes. Keep PR cookies host-only. Keep production at `www.paintedpillars.com` separate.
5. Persist environment lifecycle, readiness, last-activity, and rebuild metadata outside published logs. Cap running PR environments at three; evict the least-recently-active only to make capacity, retain it for on-demand rebuild, and do not stop an environment on merge/close.
6. Publish the ready URL and a concise diff-derived play note to the PR. Add a Windows/WSL-to-proxy/tunnel smoke-test procedure under `scripts/` documentation. Store all credentials and secrets outside the repository; add deployment state/runtime paths to `.gitignore`.

Acceptance criteria:
- [ ] Only same-repository PR branches reach checkout/build/test; fork PRs are rejected before executing or checking out PR code.
- [ ] Builds are serialized; every push rebuilds that PR; readiness is published only after isolated migration, deterministic seed, `manage.py check`, and `manage.py test` all succeed.
- [ ] Two PRs use distinct runtime ports and SQLite files; their hostnames map through one proxy and wildcard tunnel, and their session cookies are host-only.
- [ ] At most three PR environments run; capacity eviction selects the least recently active, and stopped environments are rebuildable on demand. Merge/close alone does not stop them.
- [ ] A ready PR receives its environment URL and play note; failures are visible and do not publish playable-ready status.
- [ ] PR deployments cannot use or alter production checkout/database; secrets and credentials are neither committed nor emitted in PR status/log output.
- [ ] Documented local smoke test covers Windows/WSL, proxy, and Cloudflare Tunnel routing.

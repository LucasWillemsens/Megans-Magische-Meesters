Grey out the deck, hand cards and face-down lane cards when their action budget is exhausted — with `cursor: not-allowed` on hover and rule-teaching tooltips ("Draw limit reached (Intelligence + 1 per turn)") — tilt blocked hand cards slightly upwards, hide the d/p/f counter text (kept in DOM for tests), and make the server-rendered blocked state non-interactive.

## Prerequisite

This leaf depends on `turn-allowance-backend` being implemented first (the `turnAllowances` context dict with `draws_left`/`flips_left`/`plays_left` and `blocked_titles`).

## Implementation

### 1. viewBoard.jinja2 — Deck block (lines 224-246)

When `turnAllowances.draws_left <= 0`:
- Add class `"blocked"` to `<ul class="deck">`
- Render the draw button as `class="card back draw blocked"` with `disabled` attribute and `title="{{ turnAllowances.blocked_titles.draw }}"`
- Keep the unblocked render byte-identical: `class="card back draw"` `title="Draw card"` (protects `test_enemy_deck_and_hand_have_no_interactive_hooks` asserting `class="card back draw"`)

### 2. viewBoard.jinja2 — Hand cards (lines 247-285)

When `turnAllowances.plays_left <= 0`:
- `<li>` gets class `"blocked"`
- `draggable="false"` (conditional attribute)
- `title="{{ turnAllowances.blocked_titles.play }}"`

Note: `cardDragDrop.js` binds drag only to `draggable="true"`, so blocked hand cards are natively non-draggable.

### 3. viewBoard.jinja2 — Player lane face-down cards (lines 140-163)

When `turnAllowances.flips_left <= 0`:
- `<li class="cardContainer faceDown">` gets class `"blocked"`
- `title="{{ turnAllowances.blocked_titles.flip }}"`

### 4. viewBoard.jinja2 — Counter text (lines 218-223)

Wrap the counter text in a hidden span:
```html
<span id="turnCounters" hidden>
  ( {{drawnCardsAmount}}d {{playedCardsAmount}}p {{flippedCardsAmount}}f this turn )
</span>
```
Stays in DOM for tests/debug. Deck/Hand counts stay visible.

### 5. cardDragDrop.js — setupFaceDownCardClickListeners (line 45)

Update selector to exclude blocked cards:
```javascript
'.playerBoard … .cardContainer.faceDown:not(.blocked)'
```
Ensures pre-blocked lane cards never get the one-shot flip listener. (Drag already guarded by `draggable="false"`.)

### 6. CSS (cards.css)

- `.blocked` generic: `filter: grayscale(0.85); opacity: 0.55; cursor: not-allowed` (on `li.cardContainer.blocked`, `ul.deck.blocked`, and their children including `button.draw:disabled`)
- Hand tilt: `ul.hand li.cardContainer.blocked > .card.smallCard { transform: translateY(-0.5em); }` — composes with the `li`-level `rotateHand` transforms (cards.css 517-594) since the `li` keeps its transform.
- Guard existing hover theatrics: `morphCard` hover (cardDragDrop.css 99-101) and the green backing-card slide (cards.css 1217-1221) get `:not(.blocked)`.
- `li.cardContainer.blocked:hover` keeps `cursor: not-allowed`, no `grab`.

### 7. Tests

- **Fresh board**: assertNotContains "blocked"; assertContains `class="card back draw"`; `draggable="true"` present on hand cards.
- **All-Resolve deck recipe**: After 1 draw POST → response has `class="deck blocked"` on `<ul>` and `disabled` on draw button, tooltip "Draw limit reached...".
- **Mid-turn play/flip exhaustion recipe** (2 rounds: draw, end_turn, enemy GET, draw, stage play cookie, POST draw→error): response contains hand `<li>` `class="cardContainer blocked"` with `draggable="false"`, face-down lane card `faceDown blocked` with "Flip limit reached...".
- **Counters hidden**: assertContains `id="turnCounters" hidden`. And still contains "1d".

## Acceptance criteria

- [ ] Draw limit hit → deck greyed, draw button disabled, `cursor: not-allowed`, title "Draw limit reached (Intelligence + 1 per turn)"
- [ ] Play limit hit → hand cards greyed + tilted up, `draggable="false"`, play tooltip
- [ ] Flip limit hit → face-down lane cards greyed, no flip listener (`:not(.blocked)`), flip tooltip
- [ ] d/p/f counters wrapped in hidden `#turnCounters` but still in DOM
- [ ] Unblocked board renders unchanged (existing tests green; `class="card back draw"` intact)

## Dependencies

- `turn-allowance-backend` (provides `turnAllowances` context)

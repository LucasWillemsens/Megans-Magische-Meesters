Compute remaining draw/play/flip allowances from the existing getStats() turn-limit formulas, expose them to the board template as a hidden #turnLimits data block (the backend→frontend contract for all affordance work), and pin parity with the enforcement checks in drawCard()/playCard().

## Implementation

### 1. MMM/models.py — BattleParticipant.getTurnAllowances()

Add `getTurnAllowances()` next to `getStats()` (after line 345). Mirror the three limit formulas from `drawCard()` (line 282) and `playCard()` (lines 314-315):

- `draws_left = intCount + 1 + min(0, spdCount + 1 − flippedCardsAmount − playedCardsAmount) − drawnCardsAmount`
- `flips_left = spdCount + 1 + min(0, intCount + 1 − drawnCardsAmount − playedCardsAmount) − flippedCardsAmount`
- `plays_left = 2 + tactics − drawnCardsAmount − flippedCardsAmount − playedCardsAmount`

Clamp each at 0 (`max(0, ...)`). Return a dict with:
- `draws_left`, `flips_left`, `plays_left`
- Raw ingredients the client needs to re-derive allowances while staging: `int_count`, `spd_count`, `tactics`, `drawn`, `played`, `flipped`
- Blocked title strings: `blocked_titles` dict with keys `draw`, `play`, `flip` containing rule-teaching messages like:
  - `"Draw limit reached (Intelligence + 1 per turn)"`
  - `"Play limit reached (2 + tactics − cards already played)"`
  - `"Flip limit reached (Speed + 1 per turn)"`

Comment: *"Keep in sync with drawCard()/playCard() enforcement."*

### 2. MMM/views.py — viewBoard()

Compute `allowances = current_participant.getTurnAllowances()` and add `"turnAllowances"` to the context dict (next to the existing `drawnCardsAmount` entries, views.py lines 233-235). Keep the existing counter context keys untouched.

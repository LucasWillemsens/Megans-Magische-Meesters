# Lane Card Stacking

Render multiple cards in a lane with a consistent stacked visual style that matches how hologram cards are shown.

## Solution Avenues

### Avenue 1: Traditional Card Stack (Offset Layering)
**Description**: Cards overlap with slight vertical/horizontal offsets (like a fanned hand or poker chips). Each card shows its top portion, creating a cascading stack effect. Visual depth through shadows and z-index.

**Pros**:
- Natural metaphor for "multiple cards in one space"
- Easy to implement with CSS transforms (translateY/X + z-index)
- Familiar to card game players
- Works well for 2-5 cards per lane

**Cons**:
- Can become cluttered with many cards (5+)
- Bottom cards are mostly hidden
- May conflict with hologram-row's visual style if not careful

**Complexity**: Low-Medium
**Precedent**: None in done/ (fresh implementation)

---

### Avenue 2: Thumbnail Grid
**Description**: Instead of stacking, show miniaturized card thumbnails in a compact grid within the lane. Each card gets equal visual space.

**Pros**:
- All cards visible at once (no hidden information)
- Easy to scan and count cards
- Scales well to many cards
- Clean, organized look

**Cons**:
- Less "card game" feel
- May lose visual impact of card artwork
- Requires miniaturization (small thumbnails)

**Complexity**: Low
**Precedent**: None in done/ (fresh implementation)

---

### Avenue 3: Expandable Stack
**Description**: Start with a compact stack (like Avenue 1), but expand on hover/click. Default view shows card count badge, expanded view reveals individual cards.

**Pros**:
- Best of both worlds: compact + detailed
- Interactive element adds engagement
- Clean default state, rich on-demand state
- Good for mobile (tap to expand)

**Cons**:
- More complex implementation (state management, animations)
- Hover may not work on mobile (need tap alternative)
- Requires interaction to see full information

**Complexity**: Medium-High
**Precedent**: None in done/ (fresh implementation)

---

### Avenue 4: Horizontal Spread
**Description**: Cards spread horizontally within the lane, like a poker hand arrangement. Works best for lanes with 2-4 cards.

**Pros**:
- All cards visible (like grid)
- More "hand of cards" feel than grid
- Natural left-to-right reading order
- Good for limited card counts

**Cons**:
- Doesn't scale well to many cards (5+)
- May require horizontal scrolling on narrow screens
- Different visual axis than hologram-row (which is vertical)

**Complexity**: Low-Medium
**Precedent**: None in done/ (fresh implementation)

---

## Challenge: "Is stacking the right solution?"

**Alternative Consideration**: The goal assumes stacking is the right approach, but what if we don't stack at all?

**Alternative A: Lane Divider**
- Show cards as separate entities with clear lane dividers
- Each card gets its own "slot" within the lane
- More like a board game with distinct positions

**Alternative B: Card Count Badge**
- Show only a count badge (e.g., "3 cards") in the lane
- Click/tap to see all cards in a modal or overlay
- Minimal visual clutter, maximum information density

**Alternative C: Priority Highlight**
- Show only the most recent/important card prominently
- Other cards shown as small icons or badges
- Focus attention on the active card

---

## Recommended Approach

**Avenue 1 (Traditional Stack) + Avenue 3 (Expandable) Hybrid**:
1. Start with simple offset layering (Avenue 1) as default
2. Add hover/tap expansion (Avenue 3) for detail on demand
3. Ensure visual consistency with hologram-row's pattern
4. Keep card count visible (badge or number) for quick scanning

**Rationale**:
- Matches the "consistent stacked visual style" requirement
- Provides both compactness and detail
- Familiar card game metaphor
- Scalable to different card counts

---

## Implementation Considerations

1. **CSS Architecture**: Use CSS transforms for stacking (translateY/X), box-shadow for depth, z-index for layering order
2. **Hologram Consistency**: Study hologram-row's implementation first, mirror its visual language
3. **Responsive Design**: Stack vertically on narrow screens, horizontally on wide screens
4. **Animation**: Smooth transitions when cards are added/removed from stack
5. **Accessibility**: Ensure card count and stack state are screen-reader friendly

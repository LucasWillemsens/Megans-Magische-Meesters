Clicking the face-up clone inside a flip-hologram re-fires the no-op else-branch of `onFaceDownCardClick`, stages another flip cookie, and consumes one of the player's remaining flip actions even though the card is already flipped.

## Objective
Stop the second click on a flip-hologram's face-up clone from incrementing `staged.flips` or writing a duplicate `flipFaceUp=true` cookie, without changing any other flip behavior. Extend one end-to-end JS-contract test in `MMM/tests.py` to cover it.

## Implementation

File: `var/www/static/cardDragDrop.js`

Edit 1 — flag the source lane card before cloning (minimum fix). In `onFaceDownCardClick`, inside the `if (!card.closest('.hologram'))` if-branch, insert one line right after `card.classList.add('ghost');` (currently line 1460):

Before:
```
            // Lane card stays face-down — ghostly to indicate it was flipped
            card.classList.add('ghost');

            // Create face-up hologram clone
```

After:
```
            // Lane card stays face-down — ghostly to indicate it was flipped
            card.classList.add('ghost');
            card.dataset.stagedFlipped = 'true';

            // Create face-up hologram clone
```

`card.cloneNode(true)` on line 1464 copies `dataset`, so the face-up clone inside `flipHologram` inherits `stagedFlipped='true'`. The existing guard on line 1448 (`if (card.dataset.stagedFlipped === 'true') return;`) then catches the second click before it can enter the else-branch, before `staged.flips++` on line 1510, and before the duplicate `createupdateCookie` call.

Edit 2 — belt-and-braces tighten the one-shot click handler (optional). Replace the listener currently on lines 1491-1493:

Before:
```
            // One-shot click-to-flip on the hologram (same pattern as play hologram)
            const holoCard = flipHologram.querySelector('.cardContainer');
            if (holoCard) {
                holoCard.addEventListener('click', (ev) => this.onFaceDownCardClick(ev, laneValue), { once: true });
            }
```

After:
```
            // One-shot click-to-flip on the hologram (same pattern as play hologram)
            const holoCard = flipHologram.querySelector('.cardContainer');
            if (holoCard) {
                holoCard.addEventListener('click', (ev) => {
                    if (card.dataset.stagedFlipped === 'true') return;
                    this.onFaceDownCardClick(ev, laneValue);
                }, { once: true });
            }
```

`card` (the source lane card) is still in closure scope from the enclosing `onFaceDownCardClick` call. Edit 1 alone resolves the bug; Edit 2 is defense in depth and may be omitted.

## Acceptance criteria

- [ ] `onFaceDownCardClick` flag set: the `if (!card.closest('.hologram'))` if-branch contains `card.dataset.stagedFlipped = 'true';` directly after `card.classList.add('ghost');`.
- [ ] First click on a face-down lane card increments `staged.flips` exactly once and writes exactly one `flipFaceUp=true` cookie.
- [ ] Second click on the resulting face-up clone inside the flipHologram does not increment `staged.flips` and writes no new `flipFaceUp` cookie.
- [ ] Play-hologram flip path (else-branch, line 1504) is unchanged: first click on a face-down play hologram flips it once and sets `card.dataset.stagedFlipped = 'true'`; subsequent clicks are no-ops via the line 1448 guard.
- [ ] `flipKeyboardFocusedCard` (lines 914-928) regresses identically because it forwards to `onFaceDownCardClick(event, laneValue)`; a second Enter/Space on an already-flipped card via keyboard is a no-op.
- [ ] Existing budget guard `remainingAllowances().flips <= 0` on line 1444 still short-circuits before any of the above.
- [ ] Hand ghost mirror: `_handCardForId` lookup in the else-branch (line 1506) still flags the hand ghost with `stagedFlipped='true'` on first flip.

BUG: the user can click the flip-hologram of a card that was already
flipped, which stages another flip cookie and increments
`staged.flips`, consuming the player's remaining flip budget while
the card is already being played.

This is a one-line, surgical guard in `var/www/static/cardDragDrop.js`.

The flip flow in `onFaceDownCardClick` (line 1443) is:

  1. First click on a face-down lane card.
     - `card.closest('.hologram')` is false (the lane card is not
       inside a hologram).
     - The if-branch (line 1455-1496) runs:
         * `card.classList.add('ghost')` — the lane card becomes a
           ghost (still face-down, but visually faded);
         * a new `flipHologram` (face-up clone) is created in the
           lane's `ul.hologramRow` (line 1463-1487);
         * a one-shot click listener is added to the face-up card
           inside the flipHologram (line 1490-1493):
             holoCard.addEventListener(
                 'click',
                 (ev) => this.onFaceDownCardClick(ev, laneValue),
                 { once: true },
             );
         * a hover arrow is added between the lane card and the
           flipHologram (line 1496).

  2. The user clicks the face-up card inside the flipHologram.
     - The one-shot listener fires `onFaceDownCardClick(ev, laneValue)`.
     - The `card` variable (line 1445) is the face-up card inside the
       flipHologram.
     - The check at line 1448
           `if (card.dataset.stagedFlipped === 'true') return;`
       does NOT trigger, because `stagedFlipped` is only set on the
       hand ghost (line 1507), not on the face-up clone in the holoRow.
     - The check at line 1455
           `if (!card.closest('.hologram'))`
       is also false (the face-up clone IS in the flipHologram), so
       we go to the else-branch (line 1497-1508).
     - The else-branch sets `card.dataset.stagedFlipped = 'true'`
       (line 1504) and the hand ghost's `stagedFlipped = 'true'`
       (line 1507).
     - The `staged.flips++` at line 1510 runs and consumes a flip
       from the player's budget.

So the second click on the face-up flipHologram fires the no-op
else-branch and silently consumes a flip action, even though the
card is already flipped.

The fix: gate the click handler on line 1492 on the *source* card's
`stagedFlipped` state. The source card is the original face-down
lane card. After step 1 it has the `ghost` class (line 1460), but
its `stagedFlipped` dataset is not set.

The simplest, most local fix: at the moment the click handler is
registered on line 1492, also mark the source card as
`stagedFlipped = 'true'` so the existing check at line 1448 catches
the second click. Concretely, after line 1460
(`card.classList.add('ghost');`), add:

    card.dataset.stagedFlipped = 'true';

This is the minimum-viable fix. The dataset attribute is consistent
with the way the play-hologram else-branch (line 1504) marks a card
as flipped, and the existing early-return at line 1448 already
guards on `card.dataset.stagedFlipped === 'true'`. After the change,
when the user clicks the face-up flipHologram, the second
`onFaceDownCardClick` invocation sees `card.dataset.stagedFlipped ===
'true'` (because `card` in line 1445 is the face-up clone whose
source's stagedFlipped is set, OR the face-up clone's own
stagedFlipped is set in the first invocation of the else-branch) and
returns early.

Implementation (one-line change in `var/www/static/cardDragDrop.js`):

1. In `onFaceDownCardClick`, in the if-branch
   (`if (!card.closest('.hologram'))` at line 1455, the lane-card
   flip path), after the existing
   `card.classList.add('ghost');` (line 1460), add:

       card.dataset.stagedFlipped = 'true';

   This marks the original lane card as already-flipped so the
   subsequent click on its flipHologram bails out at the existing
   line 1448 guard.

2. While we are here, make the change defensive in the else-branch
   too. The else-branch (line 1497-1508) handles "play hologram
   flipped face-up via click". It already sets
   `card.dataset.stagedFlipped = 'true'` at line 1504, which is
   correct. The hand ghost at line 1507 is also set. The existing
   line 1448 guard catches a second click on the now-face-up
   play-hologram because the holoCard's own `stagedFlipped` is
   already 'true'. So no change is needed in the else-branch;
   leave it as-is.

3. Belt-and-braces: also bail out earlier, in the click handler
   registration on line 1492, so the second click is suppressed
   *before* the listener body even runs. Replace

       holoCard.addEventListener('click', (ev) =>
           this.onFaceDownCardClick(ev, laneValue), { once: true });

   with a closure that checks the source card's flipped state and
   returns early if it is already flipped:

       const sourceCard = card;
       holoCard.addEventListener('click', (ev) => {
           if (sourceCard.dataset.stagedFlipped === 'true') {
               ev.stopPropagation();
               ev.preventDefault();
               return;
           }
           this.onFaceDownCardClick(ev, laneValue);
       }, { once: true });

   This is technically redundant with the line 1448 guard after
   step 1, but it makes the data flow explicit at the registration
   site and avoids a redundant function call. Either step 1 or
   step 3 alone fixes the bug; landing both is fine.

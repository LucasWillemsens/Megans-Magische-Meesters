## Bug 3 — Flipped ghosts remain countable for hand numbering

### Current behaviour

`cardDragDrop.js` `orderableKeyboardCards()` (lines 563-566) calls `_isOrderableKeyboardCard` (568-572) which returns true if `_isPlayableKeyboardCard` OR `_isGhostFlipCandidate`. The latter (lines 579-591) explicitly excludes `card.dataset.stagedFlipped === 'true'`.

`_confirmGhostFlipSelection` (lines 966-996) sets `card.dataset.stagedFlipped = 'true'` after a successful flip, then re-runs `applyTurnAffordances()` and clears the selection.

The result: a flipped-face-up ghost is no longer in `orderableKeyboardCards`, so its slot count disappears, causing later cards' numbers to shift. This contradicts the user's bug 3 description.

### Change

Split the predicates. Add a new method:

```js
/**
 * A staged ghost occupies its hand slot, regardless of whether it has
 * already been flipped face up. Numbering is position-based over the full
 * hand, so this card must still count.
 */
_isStagedGhost(card) {
    if (!card || !card.matches('li.cardContainer')) return false;
    if (!this.playerHandCards().includes(card)) return false;
    if (card.closest('.enemyBoard, .enemyDeckHand, .enemyHand')) return false;
    if (card.classList.contains('blocked') || card.closest('.blocked')) return false;
    if (!card.classList.contains('ghost')) return false;
    if (card.classList.contains('loading') || card.closest('.loading')) return false;
    const cardIdInput = this._cardIdInput(card);
    return Boolean(cardIdInput?.value);
}
```

Update `_isOrderableKeyboardCard`:
```js
_isOrderableKeyboardCard(card) {
    if (!card || !card.matches('li.cardContainer')) return false;
    if (this._isPlayableKeyboardCard(card)) return true;
    return this._isStagedGhost(card);
}
```

Keep `_isGhostFlipCandidate` as the ACTION predicate (only unflipped ghosts are actionable). It already excludes `stagedFlipped`, which is correct for actions.

Update `onKeyboardKeyDown`'s Enter/Space handler so flipped-face-up ghosts no-op (the existing code calls `_confirmGhostFlipSelection` which guards on `_isGhostFlipCandidate`, which returns false for flipped ghosts — so the no-op falls through to `confirmKeyboardSelection`, which only fires for playable cards, so flipped ghosts already no-op). `onHandCardClick` already routes via `playableKeyboardCards()` + `selectKeyboardCard`. Flipped-face-up ghosts are not in `playableKeyboardCards`, so the call falls through to `_selectGhostFlipCard`. But `_selectGhostFlipCard` calls `_isGhostFlipCandidate`, which returns false for flipped ghosts — so the click currently silently fails. After Bug 3, a click on a flipped ghost must select it (so it counts), but Enter/Space no-ops. Add:

```js
onHandCardClick(event) {
    ...
    const orderable = this.orderableKeyboardCards();
    const index = orderable.indexOf(card);
    if (index === -1) return;
    if (this.playableKeyboardCards().includes(card)) {
        if (!this._keyboardActionAllowed(event)) return;
        this.selectKeyboardCard(card, String(index + 1));
        return;
    }
    // Staged ghost (flipped or unflipped): select for counting.
    if (card.classList.contains('ghost')) {
        if (!this._ghostFlipInteractionAllowed(event)) {
            // flipped ghosts are still countable; only allow selection
            // for face-up flip if the budget permits
            if (card.dataset.stagedFlipped !== 'true') return;
        }
        if (card.dataset.stagedFlipped === 'true') {
            // No-op selection: focus + clear so Enter/Space does nothing.
            if (typeof card.focus === 'function') card.focus({ preventScroll: true });
            this.clearKeyboardSelection();
            return;
        }
        if (!this._ghostFlipInteractionAllowed(event)) return;
        this.selectKeyboardCard(card, String(index + 1));
    }
}

`selectOrderedCard` already routes by `_isPlayableKeyboardCard` then `_isGhostFlipCandidate`. After Bug 3, `_isOrderableKeyboardCard` returns true for flipped ghosts, but the action route via `selectOrderedCard` only fires the action for playable + `_isGhostFlipCandidate`. ```js
selectOrderedCard(card, digitBuffer, event) {
    if (this._isPlayableKeyboardCard(card)) {
        if (!this._keyboardActionAllowed(event)) return;
        this.selectKeyboardCard(card, digitBuffer);
        return;

    if (this._isGhostFlipCandidate(card)) {
        if (!this._ghostFlipInteractionAllowed(event)) return;
        this.selectKeyboardCard(card, digitBuffer);
        return;
    }
    // Flipped-face-up ghost: still countable but no action.
    if (card.dataset.stagedFlipped === 'true' && card.classList.contains('ghost')) {
        if (typeof card.focus === 'function') card.focus({ preventScroll: true });
        this.clearKeyboardSelection();
    }
}
```

## Bug 4 — Keyboard focus on hand card shows hover arrow

### Current behaviour

`_addHoverArrow` (lines 1335-1369) binds only `mouseenter`/`mouseleave` on `sourceEl` and `targetEl`.

### Change

Add `focusin`/`focusout` on `sourceEl` (only — `targetEl` already gets a `:focus-within` lift via CSS so we don't need to trigger the arrow from target focus).

```js
_addHoverArrow(sourceEl, targetEl) {
    let arrow = null;
    let hideTimeout = null;

    const showArrow = () => {
        if (hideTimeout) {
            clearTimeout(hideTimeout);
            hideTimeout = null;
        }
        if (!arrow || !arrow.parentNode) {
            arrow = this._createCurvedArrow(sourceEl, targetEl);
            document.body.appendChild(arrow);
        }
        sourceEl.classList.add('hover');
        targetEl.classList.add('hover');
    };

    const hideArrow = () => {
        if (hideTimeout) return;
        hideTimeout = setTimeout(() => {
            if (arrow && arrow.parentNode) arrow.remove();
            arrow = null;
            sourceEl.classList.remove('hover');
            targetEl.classList.remove('hover');
            hideTimeout = null;
        }, 100);
    };

    sourceEl.addEventListener('mouseenter', showArrow);
    sourceEl.addEventListener('mouseleave', hideArrow);
    sourceEl.addEventListener('focusin', showArrow);   // NEW
    sourceEl.addEventListener('focusout', hideArrow);   // NEW
    targetEl.addEventListener('mouseenter', showArrow);
    targetEl.addEventListener('mouseleave', hideArrow);
}
```

The 100 ms `hideTimeout` cooldown handles Tab moves between source/target without flicker. The target hologram's `:focus-within` lift (cards.css line 153-156) is independent of the arrow.

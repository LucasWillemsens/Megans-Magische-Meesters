Refactor the scattered keyboard predicates in
`var/www/static/cardDragDrop.js` into one cohesive
`KeyboardSelectionControl` class. The new control owns the
`selectedCard` / `cardId` / `sourceLane` / `sourceOrdinal` /
`laneValue` / `currentLane` / `hologram` / `rotation` /
`digitBuffer` / `ghostFlip` state, the `focusin`/`focusout`
bindings (for the hover-arrow wiring in
`focus-arrow-bindings-20261012/`), the per-card playability
predicate, and the `selectKeyboardCard` /
`moveKeyboardSelection` / `confirmKeyboardSelection` /
`clearKeyboardSelection` API.

The existing tests that pin the old predicate shape
(`test_keyboard_selection_contract_uses_playable_fans_and_preview_hooks`,
`test_ghost_card_numbering_and_flip_contract`,
`test_keyboard_confirmation_contract_preserves_staging_and_guards`,
and the contract tests in `test_turn_affordances_block_hand_cards_out_of_tab_order_and_restore_idempotently`)
are rewritten as part of this subdirectory to pin the new
control's API.

This is the JS half of the broader keyboard navigation
goal. It depends on no other subdirectory; the
`arrow-key-routing-20261012` subdirectory consumes the new
control's `navigate(direction, fromElement)` API.

User decisions captured in the source description:

- Unit tests pinned to the old scattered focus/select
  predicates are rewritten as part of the refactor. This
  subdirectory is the right place to do that.
- `_addHoverArrow` already works as-is. The new control
  just hooks into it on `focusin`/`focusout`. The
  actual wiring (which element fires the `focusin` for
  which target) lives in `focus-arrow-bindings-20261012/`.

Background — the old scattered surface to consolidate:

The current `cardDragDrop.js` mixes the per-card predicate,
the selection state, the per-stage helper, and the
keyboard event routing all inside `CardDragDropSystem`.
Specifically:

- `keyboardSelection` field (line 133) holds the selection
  state.
- `_emptyKeyboardSelection()` (line 142) resets it.
- `playableKeyboardCards()` (line 218) filters hand cards.
- `orderableKeyboardCards()` (line 570) filters hand cards
  including staged ghosts.
- `_isPlayableKeyboardCard(card)` (line 544) — predicate
  for un-staged, un-blocked hand cards.
- `_isStagedGhost(card)` (line 559) — predicate for
  ghosted hand cards.
- `_isOrderableKeyboardCard(card)` (line 575) — composite
  predicate (playable OR staged ghost).
- `_isGhostFlipCandidate(card)` (line 582) — predicate for
  a ghost that can still be flipped face-up.
- `_handCardForId(cardId)` (line 602) — lookup.
- `_stagedLaneForGhost(card)` (line 596) — dataset lookup
  for the ghost's target lane.
- `selectKeyboardCard`, `moveKeyboardSelection`,
  `confirmKeyboardSelection`, `clearKeyboardSelection`,
  `cancelKeyboardSelection` (lines 1004-1154) — selection
  API.
- `onKeyboardKeyDown` (line 775) — keydown event router.
- `flipKeyboardFocusedCard` (line 914) — keyboard flip
  helper.
- `_keyboardHologramRow`, `_keyboardFlipTarget`,
  `_selectGhostFlipCard`, `_confirmGhostFlipSelection`,
  `_isKeyboardActionAllowed`, `_isGhostFlipInteractionAllowed`,
  `_isKeyboardTransitionActive`, `_isTextControlTarget`,
  `_isDisabledControlTarget` (lines 423-940) — supporting
  helpers.
- `_addHoverArrow` (line 1350) — focusin/focusout listener
  binding (used by both play and flip flows).

The refactor pulls the selection state, predicates, and
public API into a new `KeyboardSelectionControl` class and
keeps `CardDragDropSystem` as the orchestrator.

Implementation:

1. `var/www/static/cardDragDrop.js` — extract the new class.

   a. Add a new class `KeyboardSelectionControl` near the
      top of the file (after `ShortcutHoldAction`, before
      `CardDragDropSystem`):

          class KeyboardSelectionControl {
              constructor({
                  cardDragDrop,         // back-reference to
                                         // CardDragDropSystem
                  handCards,            // () => Element[]
                  playablePredicate,    // (card) => boolean
                  ghostFlipPredicate,   // (card) => boolean
                  ghostPredicate,       // (card) => boolean
                  buildPlayHologram,    // (card, lane, keyboardPreview, rotation) => Element|null
                  keyboardHologramRow,  // (lane) => Element|null
                  stagePlay,            // (card, lane, hologram, preservePreview, sourceState) => boolean
                  createupdateCookie,   // (cardId, lane, flip, sourceLane, sourceOrdinal) => void
                  clearPreview,         // () => void
              } = {}) {
                  this.cardDragDrop = cardDragDrop;
                  this.handCards = handCards;
                  this.playablePredicate = playablePredicate;
                  this.ghostFlipPredicate = ghostFlipPredicate;
                  this.ghostPredicate = ghostPredicate;
                  this.buildPlayHologram = buildPlayHologram;
                  this.keyboardHologramRow = keyboardHologramRow;
                  this.stagePlay = stagePlay;
                  this.createupdateCookie = createupdateCookie;
                  this.clearPreview = clearPreview;
                  this.state = this._empty();
              }

              _empty() {
                  return {
                      selectedCard: null,
                      cardId: null,
                      sourceLane: null,
                      sourceOrdinal: null,
                      laneValue: null,
                      currentLane: null,
                      hologram: null,
                      rotation: null,
                      digitBuffer: '',
                      ghostFlip: false,
                  };
              }

              get hasSelection() {
                  return Boolean(this.state.selectedCard || this.state.digitBuffer);
              }

              get selectedCard() { return this.state.selectedCard; }
              get currentLane() { return this.state.currentLane; }
              get digitBuffer() { return this.state.digitBuffer; }
              get ghostFlip() { return this.state.ghostFlip; }
              get hologram() { return this.state.hologram; }

              // ... rest of the API ...
          }

   b. Move the following methods from `CardDragDropSystem`
      to `KeyboardSelectionControl` as instance methods:

      - `selectKeyboardCard(card, digitBuffer)` — public.
        Replaces the existing `CardDragDropSystem.selectKeyboardCard`.
        Internally dispatches to `_selectGhostFlipCard` when
        the card matches `ghostFlipPredicate`, otherwise
        builds a play hologram and stages the selection.
      - `moveKeyboardSelection(laneValue)` — public.
        Replaces `CardDragDropSystem.moveKeyboardSelection`.
        Rebuilds the hologram in the new lane.
      - `confirmKeyboardSelection(laneValue)` — public.
        Replaces `CardDragDropSystem.confirmKeyboardSelection`.
        Calls `stagePlay` with the selected card + lane.
      - `clearKeyboardSelection({removePreview} = {})` —
        public. Replaces
        `CardDragDropSystem.clearKeyboardSelection`.
        Optionally removes the keyboard-preview hologram.
      - `cancelKeyboardSelection()` — thin alias.
      - `_selectGhostFlipCard(card, digitBuffer)` — private
        helper, replaces
        `CardDragDropSystem._selectGhostFlipCard`.
      - `_confirmGhostFlipSelection(event)` — private
        helper, replaces
        `CardDragDropSystem._confirmGhostFlipSelection`.

   c. Replace the `_isPlayableKeyboardCard` /
      `_isStagedGhost` / `_isOrderableKeyboardCard` /
      `_isGhostFlipCandidate` / `_stagedLaneForGhost` /
      `_handCardForId` predicates on `CardDragDropSystem`
      with delegation calls to the new control:

          _isPlayableKeyboardCard(card) {
              return this.playablePredicate(card);
          }
          _isStagedGhost(card) {
              return this.ghostPredicate(card);
          }
          _isOrderableKeyboardCard(card) {
              return this.playablePredicate(card) || this.ghostPredicate(card);
          }
          _isGhostFlipCandidate(card) {
              return this.ghostFlipPredicate(card);
          }

      The actual predicates are constructed in
      `CardDragDropSystem.init` and passed to the control's
      constructor (the `playablePredicate`, `ghostPredicate`,
      `ghostFlipPredicate` arrow functions).

      The arrow functions close over the playerBoard,
      handCards, and remainingAllowances references and
      inline the same logic as the old methods. The
      rewrite keeps the test-friendly predicates visible
      on the `CardDragDropSystem` so existing tests that
      inspect `this._isPlayableKeyboardCard` still find
      the method (just as a delegating wrapper).

   d. Move the `keyboardSelection` field off
      `CardDragDropSystem`. Replace all internal reads
      (`this.keyboardSelection.selectedCard`, etc.) with
      `this.keyboardSelectionControl.state.X` or the
      getter `this.keyboardSelectionControl.selectedCard`.
      Keep the public-ish `this.keyboardSelection` field
      as a getter that returns the control's state for
      backward compatibility with the (rewritten) tests
      and any external scripts that probe it.

   e. Wire the focusin/focusout events that the
      `focus-arrow-bindings-20261012/` subdirectory will
      use. The new control exposes:

          onFocusIn(card) { /* show arrow from card → state.hologram */ }
          onFocusOut(card) { /* hide arrow */ }

      In this subdirectory these are stub no-ops; the
      next subdirectory fills in the `_addHoverArrow`
      call. The stubs ensure the wiring points are in
      place.

2. `var/www/static/cardDragDrop.js` — refactor the
   `onKeyboardKeyDown` event router (line 775) to delegate
   the digit-buffer, cancel, flip, and confirm branches to
   the new control's public API. The router remains on
   `CardDragDropSystem` (it owns the event listener), but
   every action calls into the control:

       if (key === '0' || key === 'Backspace') {
           if (!this.keyboardSelectionControl.hasSelection) return;
           this._cancelKeyboardSelectionFromEvent(event);
           return;
       }

       if (key === 'Escape') {
           if (!this.keyboardSelectionControl.hasSelection) return;
           this._cancelKeyboardSelectionFromEvent(event);
           return;
       }

       if (!this.keyboardSelectionControl.hasSelection
           && (key === 'Enter' || key === ' ')) {
           this.flipKeyboardFocusedCard(event);
           return;
       }

       if (this.keyboardSelectionControl.selectedCard
           && (key === 'Enter' || key === ' ' || ...)) {
           if (this.keyboardSelectionControl.ghostFlip) {
               if (this._confirmGhostFlipSelection(event)) event.preventDefault();
               return;
           }
           ...
           if (this.keyboardSelectionControl.confirm()) event.preventDefault();
           return;
       }

   The exact branch order matches the existing
   `onKeyboardKeyDown`; only the call sites change.

Notes / risks:
- The refactor is large. Expect a single PR with the
  new class extracted, the predicates re-bound, the
  event router simplified, and four tests rewritten.
  The end-to-end behavior must be byte-identical
  from the user's perspective: the same keys do the
  same things in the same situations.
- The `legacy` predicate methods
  (`_isPlayableKeyboardCardLegacy` etc.) are
  intentionally kept as private members. They are
  the only place the per-card predicate logic lives;
  the new control consumes them via the constructor
  arrow functions. This keeps the logic in one
  place and the new control free of hand-card
  knowledge.
- The `digitBuffer` field is initialized to the empty
  string in `_empty()`, matching the old
  `_emptyKeyboardSelection()` behavior (line 152).
  The control's `hasSelection` getter returns true
  when either `selectedCard` is set or `digitBuffer`
  is non-empty.
- The new control's `selectKeyboardCard(card,
  digitBuffer)` returns true on success, false on
  failure, matching the old method's contract
  (line 1004). The new control's
  `confirmKeyboardSelection(laneValue)` likewise
  returns a boolean.

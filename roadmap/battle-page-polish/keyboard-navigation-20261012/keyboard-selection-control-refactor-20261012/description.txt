Refactor the scattered keyboard predicates in `cardDragDrop.js` into one cohesive `KeyboardSelectionControl` class. The new control owns the selection state, the per-card playability predicates, the focusin/focusout bindings (for the hover-arrow wiring in `focus-arrow-bindings`), and the public selection API.

## Behavior

- A new `KeyboardSelectionControl` class owns the keyboard selection state, predicates, and public API.
- `CardDragDropSystem` retains its public API surface (`playableKeyboardCards`, `orderableKeyboardCards`, `applyTurnAffordances`, `onHandCardClick`, `onDropZoneClick`) but delegates the keyboard selection logic to the new control.
- The end-to-end keyboard behavior is identical from the user's perspective: the same keys do the same things in the same situations.
- The end-turn / draw hold flows (E / D keys via `ShortcutHoldAction`) and the drag-and-drop flow are unchanged.
- The four existing tests that pin the old scattered predicate shape are rewritten to pin the new control's API.
- `CardDragDropSystem.destroy()` nulls out the new control so re-init starts with fresh state.

## Code locations

- `var/www/static/cardDragDrop.js` — extract `KeyboardSelectionControl` near the top of the file (after `ShortcutHoldAction`, before `CardDragDropSystem`); refactor `onKeyboardKeyDown` to delegate to the control's public API.

## Implementation notes

- The old scattered surface lives across `CardDragDropSystem`: `keyboardSelection` field, `_emptyKeyboardSelection()`, `playableKeyboardCards()`, `orderableKeyboardCards()`, `_isPlayableKeyboardCard()`, `_isStagedGhost()`, `_isOrderableKeyboardCard()`, `_isGhostFlipCandidate()`, `_handCardForId()`, `_stagedLaneForGhost()`, the public `selectKeyboardCard` / `moveKeyboardSelection` / `confirmKeyboardSelection` / `clearKeyboardSelection` / `cancelKeyboardSelection`, and the supporting helpers (`flipKeyboardFocusedCard`, `_keyboardHologramRow`, `_keyboardFlipTarget`, etc.).
- Move selection state, predicates, and the public selection API into the new class. Construct the predicates as arrow functions in `CardDragDropSystem.init()` and pass them to the control's constructor.
- Keep the existing predicate methods on `CardDragDropSystem` as delegating wrappers (renamed to a `_Legacy` suffix on the actual implementations) so rewritten tests can still find them.
- Stub the focusin/focusout hook points (`onFocusIn(card)`, `onFocusOut(card)`) on the new control; the next goal (`focus-arrow-bindings`) fills in the `_addHoverArrow` calls.

## Acceptance criteria

- `KeyboardSelectionControl` class exists in `cardDragDrop.js`.
- `CardDragDropSystem` public API still works (delegated).
- The four existing keyboard-selection tests are rewritten and pass.
- End-turn / draw hold flows and drag-and-drop are unchanged.

## Notes

- `CardDragDropSystem.keyboardSelection` stays as a getter returning the new control's state for back-compat with rewritten tests and external scripts that probe it.
- Predicates are passed to the control as constructor arrow functions that close over `playerBoard` / `handCards` / `remainingAllowances`. The control stays free of hand-card knowledge.

## Dependencies

- No dependency on other `keyboard-navigation-20261012/` subgoals.
- Independent of sibling `hologram-flip-click-fix-20261012` (the refactor preserves the existing `stagedFlipped` dataset semantics).
- The `arrow-key-routing-20261012` and `focus-arrow-bindings-20261012` subgoals build on the new control.

Add an integer field `focusedHandCard` (default 1) on `BattleParticipant` that remembers the 1-based ordinal of the last hand card the player focused, across turns and page reloads. Expose the value to the board template as `data-focused-hand-card` on `#turnLimits` so the JS can restore focus to the correct slot.

## Behavior

- A new `BattleParticipant.focusedHandCard` integer field exists with default 1.
- The field is intentionally NOT reset on end-turn — the focus "remembers" across turns, only changing when the player explicitly changes it.
- `getTurnAllowances()` returns the value so the template can read it.
- The board response carries `data-focused-hand-card="{{ value }}"` on `#turnLimits`.
- The end-turn form carries a hidden input `name="focused_hand_card"` whose value is updated by the JS as the player navigates; the next action POST saves the value back to the participant.
- Out-of-range POST values are silently rejected (matches the existing "stale cookie" tolerance in `playcards`).

## Acceptance criteria

- `BattleParticipant.focusedHandCard` exists, defaults to 1, and is preserved across `resetTurn()` calls.
- Migration `0015_battleparticipant_focusedhandcard.py` is generated by `makemigrations` and applies cleanly.
- `getTurnAllowances()` returns `focused_hand_card` (defaults to 1 on a fresh participant).
- Board response carries `data-focused-hand-card="{{ value }}"` on `#turnLimits` and a hidden input `name="focused_hand_card"` on the end-turn form (with the same value).
- POSTing `focused_hand_card=4` (as a string) followed by a save reads back `4` on the participant.
- POSTing `focused_hand_card="abc"`, `focused_hand_card="0"`, or `focused_hand_card="10000"` is silently rejected (matches the existing `playcards` cookie tolerance).
- `selectKeyboardCard` updates the hidden input's `value` to the `digitBuffer` it just stored, so the next form submit carries the latest selection.

## Notes

- Field is intentionally NOT reset in `resetTurn()` — focus "remembers" across turns. If the desired behavior is "reset on end-turn", the reset belongs in `resetTurn`.
- POSTed-value cap is `1..6561` (defensive; the real upper bound is the hand size). Out-of-range values are silently rejected (matches the existing "stale cookie" tolerance in `playcards`).
- The hidden input lives on the end-turn form only; the draw form does not need it (every turn ends with end-turn).

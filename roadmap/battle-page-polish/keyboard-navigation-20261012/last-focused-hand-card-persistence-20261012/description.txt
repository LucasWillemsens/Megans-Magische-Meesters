Add an integer field `focusedHandCard` (default 1) on `BattleParticipant` that remembers the 1-based ordinal of the last hand card the player focused, across turns and page reloads. Expose the value to the board template as `data-focused-hand-card` on `#turnLimits` so the JS can restore focus to the correct slot.

## Behavior

- A new `BattleParticipant.focusedHandCard` integer field exists with default 1.
- The field is intentionally NOT reset on end-turn — the focus "remembers" across turns, only changing when the player explicitly changes it.
- `getTurnAllowances()` returns the value so the template can read it.
- The board response carries `data-focused-hand-card="{{ value }}"` on `#turnLimits`.
- The end-turn form carries a hidden input `name="focused_hand_card"` whose value is updated by the JS as the player navigates; the next action POST saves the value back to the participant.
- Out-of-range POST values are silently rejected (matches the existing "stale cookie" tolerance in `playcards`).

## Code locations

- `MMM/models.py` — new field on `BattleParticipant`; new key in `getTurnAllowances()`.
- `MMM/migrations/0015_battleparticipant_focusedhandcard.py` — new migration generated by `makemigrations`.
- `MMM/views.py` — read `focused_hand_card` from POST in `boardAction` and save it on the participant.
- `MMM/jinja2/MMM/battle/viewBoard.jinja2` — add `data-focused-hand-card` on `#turnLimits`; add the hidden input to the end-turn form.
- `var/www/static/cardDragDrop.js` — keep the hidden input in sync inside `selectKeyboardCard` (or, pre-refactor, the existing `selectKeyboardCard`).

## Implementation notes

- Field: `focusedHandCard = models.IntegerField(default=1)`. No `max_length`, validators, or choices.
- Read the value from the POST in `boardAction` after `action = request.POST.get("action", "")`. If the value is a digit in range, save it with `update_fields=["focusedHandCard"]`.
- The hidden input is updated synchronously in `selectKeyboardCard` (or in the new `KeyboardSelectionControl` after the refactor) using the `digitBuffer` (the 1-based ordinal string from `_noZeroOrdinal`) so multi-digit selections are preserved.

## Acceptance criteria

- New `BattleParticipant.focusedHandCard` field exists, default 1.
- Migration is generated and applies cleanly.
- `getTurnAllowances()` returns `focused_hand_card`.
- Board response carries `data-focused-hand-card` on `#turnLimits` and the hidden input on the end-turn form.
- POSTing `focused_hand_card=4` followed by a save reads back 4 on the participant.
- The JS keeps the hidden input in sync with the currently-focused hand card slot.

## Notes

- Field is intentionally NOT reset in `resetTurn()` — focus "remembers" across turns. If the desired behavior is "reset on end-turn", the reset belongs in `resetTurn`.
- POSTed-value cap is `1..9 * 9 * 9 * 9 = 6561` (defensive; the real upper bound is the hand size). Out-of-range values are silently rejected (matches the existing "stale cookie" tolerance in `playcards`).
- The hidden input lives on the end-turn form only; the draw form does not need it (every turn ends with end-turn).

## Dependencies

- None on other `keyboard-navigation-20261012/` subgoals; can be landed independently.
- Consumed by `arrow-key-routing-20261012/` via the data attribute and hidden input.
- Independent of the other battle-page-polish siblings.

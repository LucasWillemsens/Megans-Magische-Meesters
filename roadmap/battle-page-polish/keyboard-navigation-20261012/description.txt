Arrow-key navigation:
- Up from hand → upmost left focusable field card
- Down from field → hand, at the last-focused hand card position.
- Up from field → end turn button.
- Down from hand → end turn button.
- Down from end turn → draw button.
- Up from end turn → hand, at the last-focused hand card.
- Down from draw → hand, at the last-focused hand card.
- Up from draw → end turn.
- Last-focused hand card is remembered across turns and across page reloads (persist via #turnLimits data block or similar server-rendered state).

Refactor:
- One clean keyboard selection control replaces the scattered focus/select helpers.
- All existing tests that pin the old predicate shape are rewritten.
- _addHoverArrow binding extends naturally: focusin on a hand card that's been played (face up or face down) shows the arrow to its lane target. Focusin on a ghost of a played card shows the arrow to where it's played. Focusin on a face-down lane card that's been flipped shows the arrow to the flip hologram. 

Debug overlay (player-facing):
- The backtick key (`) toggles visibility of three elements:
  - The first `<p>` in the player deckHand.
  - The first `<p>` in the enemy deckHand.
  - The lane indicator `<p>` (the value / name `<p>` inside each lane).
- When visible, all three get the shared CSS class with `position: absolute; background: white; z-index: 3;` — a floating white panel-style overlay.
- Invisible by default.
- This is an inspectable debug-style UI, accessible to players via the backtick key.

The "last focused hand card" is persisted across page reloads as a new integer value in the battleparticipant model. It is loaded into the cardselection input as if the player manually typed the associated number. The input defaults to 1. Moving up from the endturn or down from draw loads the value and focusses / selects the associated hand card.

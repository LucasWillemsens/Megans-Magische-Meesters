Wire the arrow keys (Up, Down, Left, Right) to move focus
between the four regions on the board: hand cards, field
cards, end-turn button, draw button. The new
`KeyboardSelectionControl` (from
`keyboard-selection-control-refactor-20261012/`) exposes a
`navigate(direction, fromElement)` API; this subdirectory
implements the API and integrates the persisted
last-focused hand card value (from
`last-focused-hand-card-persistence-20261012/`) so the
hand region recalls the player's previous focus position.

The user-provided route table (verbatim from the source
description):

- Up from hand → upmost left focusable field card
- Down from field → hand, at the last-focused hand card
  position.
- Up from field → end turn button.
- Down from hand → end turn button.
- Down from end turn → draw button.
- Up from end turn → hand, at the last-focused hand card.
- Down from draw → hand, at the last-focused hand card.
- Up from draw → end turn.

Background:

The new `KeyboardSelectionControl` (added in the
refactor subdirectory) owns the keyboard selection state.
This subdirectory adds a `navigate(direction,
fromElement)` method on the control and a small helper
class (`RegionNavigator`) that knows the four regions
(hand, field, end-turn, draw) and can resolve a focus
target for a given (direction, current region) pair.

The "last-focused hand card position" comes from the
`data-focused-hand-card` attribute on `#turnLimits` (added
in `last-focused-hand-card-persistence-20261012/`). On
initial render the JS reads this attribute and stores it as
the default focus target for the hand region. The
`selectKeyboardCard` method (already updated in the
refactor subdirectory) updates a hidden input on the
end-turn form so the next action POST persists the
updated value; this subdirectory wires the read side.

Implementation:

1. `var/www/static/cardDragDrop.js` — add a small
   `RegionNavigator` class near the
   `KeyboardSelectionControl` definition:

       const REGIONS = {
           HAND: 'hand',
           FIELD: 'field',
           END_TURN: 'end-turn',
           DRAW: 'draw',
       };

       class RegionNavigator {
           constructor(cardDragDrop) {
               this.cardDragDrop = cardDragDrop;
           }

           resolveRegion(element) {
               if (!element || typeof element.closest !== 'function') return null;
               if (element.closest('.playerScreen .deckHand .end-turn')) return REGIONS.END_TURN;
               if (element.closest('.playerScreen .deckHand .active-deck button.draw')) return REGIONS.DRAW;
               if (element.closest('.playerScreen .deckHand .hand-scroll .hand-fan')) return REGIONS.HAND;
               if (element.closest('.playerBoard .lane, .hologram')) return REGIONS.FIELD;
               return null;
           }

           focusableTargets(region) {
               switch (region) {
                   case REGIONS.HAND:
                       return Array.from(this.cardDragDrop.playerHandCards())
                           .filter((card) =>
                               card.hasAttribute('tabindex') &&
                               !card.classList.contains('blocked'));
                   case REGIONS.FIELD: {
                       const cards = Array.from(
                           this.cardDragDrop.playerBoard?.querySelectorAll(
                               '.playerBoard .lane ul.cardRow[title="cards"] li.cardContainer[tabindex="0"], ' +
                               '.hologram.keyboard-staged .cardContainer[tabindex="0"]'
                           ) || []
                       );
                       return cards;
                   }
                   case REGIONS.END_TURN:
                       return [document.querySelector('.playerScreen .end-turn')].filter(Boolean);
                   case REGIONS.DRAW:
                       return [document.querySelector('.playerScreen .deckHand .active-deck button.draw:not(:disabled)')].filter(Boolean);
                   default:
                       return [];
               }
           }

           upmostLeft(fieldCards) {
               // "Upmost left" = the focusable field card with the
                   // smallest offsetTop; tiebreak by smallest offsetLeft.
                   return fieldCards.slice().sort((a, b) => {
                       const ay = a.getBoundingClientRect().top;
                       const by = b.getBoundingClientRect().top;
                       if (ay !== by) return ay - by;
                       return a.getBoundingClientRect().left - b.getBoundingClientRect().left;
                   })[0] || null;
           }

           handTargetAtSlot(slot) {
               const cards = this.focusableTargets(REGIONS.HAND);
               if (cards.length === 0) return null;
               const index = Math.max(0, Math.min(slot - 1, cards.length - 1));
               return cards[index];
           }

           lastFocusedHandSlot() {
               const limits = document.getElementById('turnLimits');
               const raw = limits?.dataset?.focusedHandCard;
               const parsed = Number.parseInt(raw, 10);
               return Number.isFinite(parsed) && parsed >= 1 ? parsed : 1;
           }
       }

2. `var/www/static/cardDragDrop.js` — add a `navigate`
   method on the new `KeyboardSelectionControl`:

       navigate(direction, fromElement) {
           const navigator = this.regionNavigator;
           const region = navigator.resolveRegion(fromElement);
           if (!region) return false;

           const route = {
               [REGIONS.HAND]: {
                   Up: () => navigator.upmostLeft(navigator.focusableTargets(REGIONS.FIELD)),
                   Down: () => navigator.focusableTargets(REGIONS.END_TURN)[0] || null,
               },
               [REGIONS.FIELD]: {
                   Up: () => navigator.focusableTargets(REGIONS.END_TURN)[0] || null,
                   Down: () => navigator.handTargetAtSlot(navigator.lastFocusedHandSlot()),
               },
               [REGIONS.END_TURN]: {
                   Up: () => navigator.handTargetAtSlot(navigator.lastFocusedHandSlot()),
                   Down: () => navigator.focusableTargets(REGIONS.DRAW)[0] || null,
               },
               [REGIONS.DRAW]: {
                   Up: () => navigator.focusableTargets(REGIONS.END_TURN)[0] || null,
                   Down: () => navigator.handTargetAtSlot(navigator.lastFocusedHandSlot()),
               },
           };

           const target = route[region]?.[direction]?.();
           if (target && typeof target.focus === 'function') {
               target.focus({ preventScroll: true });
               if (region === REGIONS.HAND) {
                   // also select via the keyboard selection control
                   // so the hidden input on the end-turn form tracks
                   // the new focus position.
                   this.selectKeyboardCard(target, this._ordinalForCard(target));
               }
               return true;
           }
           return false;
       }

Notes / risks:
- The "upmost left" rule for Up-from-hand sorts by
  `getBoundingClientRect().top` ascending then
  `getBoundingClientRect().left` ascending. This works
  for the current layout where all four lanes are
  side-by-side and a single "topmost" lane exists.
  After `board-overflow-into-enemy-20261012/` lands,
  the upmost-left field card may be in an overflow
  row above the first row; the sorting still works
  because the overflow rows are positioned absolutely
  within the lane and their bounding rects are above
  the first row.
- The `focusableTargets(REGIONS.FIELD)` selector
  targets both lane cards and keyboard-staged
  holograms. A keyboard-staged hologram is a face-down
  clone placed in the holoRow when the player confirms
  a play; it has `tabindex="0"` if flips remain. Up
  from hand focuses the upmost-left of these.
- The navigate method returns true when focus moves
  and false otherwise (e.g. ArrowDown from a hand card
  with no end-turn button visible, which should not
  happen in normal play but is defensive). The caller
  calls `event.preventDefault()` only on true.
- The hidden input is updated synchronously inside
  `selectKeyboardCard`; the persistence round-trip is
  on the next action POST (end-turn or draw). This
  matches the "remembered across turns" intent in
  the source description.

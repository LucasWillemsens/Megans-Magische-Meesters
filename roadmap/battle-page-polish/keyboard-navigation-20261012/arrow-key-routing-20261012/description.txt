Wire the arrow keys (Up, Down, Left, Right) to move focus between the four regions on the board: hand cards, field cards, end-turn button, draw button. The new `KeyboardSelectionControl` exposes a `navigate(direction, fromElement)` API; this goal implements the API and integrates the persisted last-focused hand card value.

## Route table (verbatim)

- Up from hand → upmost-left focusable field card.
- Down from field → hand, at the last-focused hand card slot.
- Up from field → end-turn button.
- Down from hand → end-turn button.
- Down from end-turn → draw button.
- Up from end-turn → hand, at the last-focused hand card slot.
- Down from draw → hand, at the last-focused hand card slot.
- Up from draw → end-turn button.
- ArrowLeft/Right inside the field with a selected card: continue cycling lanes via the existing `moveKeyboardSelection`.

## Code locations

- `var/www/static/cardDragDrop.js` — add `RegionNavigator`, add `navigate(direction, fromElement)` to `KeyboardSelectionControl`, wire arrow keys in `onKeyboardKeyDown`.

## Implementation notes

- `RegionNavigator` resolves the current region from `document.activeElement` and returns the focusable targets for each of the four regions (hand, field, end-turn, draw).
- "Upmost-left" field card sorts by `getBoundingClientRect().top` ascending, tiebreak by `left` ascending. The sort continues to work after `board-overflow-into-enemy-20261012` lands because overflow rows are positioned absolutely within their lane.
- The last-focused hand card slot is read from `data-focused-hand-card` on `#turnLimits` (set up by `last-focused-hand-card-persistence-20261012`).
- When the navigate method lands on a hand card, also update the persisted last-focused hand card via `selectKeyboardCard`, which writes to the hidden input on the end-turn form.

## Acceptance criteria

- The eight region/direction routes above focus the correct element.
- The last-focused hand card slot is loaded from `data-focused-hand-card` on render.
- Updating the focused hand card (via select or navigate) writes the new value to the `focusedHandCardInput` hidden input.
- POSTing end-turn with the hidden input persists the new value on the participant.
- The existing ArrowLeft/Right lane-cycle path (`moveKeyboardSelection`) is preserved when a card is selected.

## Notes

- "Upmost-left" sorts by `getBoundingClientRect().top` then `.left` ascending. Continues to work after `board-overflow-into-enemy-20261012` lands because overflow rows are absolutely positioned within their lane and have smaller `.top` than the first row.
- HologramRow cards are treated as part of the FIELD region — no special routing.

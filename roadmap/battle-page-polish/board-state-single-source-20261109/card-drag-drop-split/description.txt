Split the battle board script along its seams — keyboard selection, region navigation, shortcut hold, and hologram arrows each become their own module, and the cascading keydown handler becomes a data-driven key-route table. Behavior-preserving — no product changes; every keyboard, drag, and flip behavior works exactly as before, and the board's script entry points stay stable for the other board scripts and the test harnesses.

Objective + end-to-end intent: a player who never reads code notices nothing. The full keyboard/drag/flip surface below still passes through the existing fake-DOM execution tests and rendered-DOM tests, now pointed at module entry points instead of one file's internals.

Implementation:
1. Extract, along the existing class seams in var/www/static/cardDragDrop.js: the shortcut-hold action, the region navigator, the keyboard selection control, and the hologram/curved-arrow drawing (hover arrows and focus arrows together). Each gets its own file under var/www/static/, loaded by the board template through the same script-tag pattern it already uses. The drag/drop core (drop zones, staging cookies, hologram building, mouse and touch drags, affordance application) remains the root module.
2. Kill the _Legacy shim layer while extracting the keyboard selection control: today each predicate is defined as a closure on the root system, wrapped in a _Legacy-suffixed method on the control, and re-exposed under its original name back on the system — three hops for one question. After the split each predicate has exactly one owner and one name, and the control and the root stop re-exposing each other.
3. Keep the board's script contract stable: the root module still initializes on DOMContentLoaded and exposes the same window global with the public surface the fake-DOM test harnesses drive (frontend-tests.txt lists the harness expectations); no other board script is forced to change how it loads.
4. Decompose the keydown handler into a key-route table: each route — overlay toggle, end-turn, draw, selection cancel, confirm-activate, confirm, region navigation, lane cycle, hand cycle, fan stepping, digit selection — is a named entry with its own guard, and the dispatcher picks a route data-driven from the key and the current selection state instead of walking a cascading if-chain. The route precedence must reproduce the current chain's exactly (the scratchpad lists the order); an unmatched key stays a no-op.
5. Rebase the tests that pin the old shape: every test that slices a method body out of the board script, asserts a _Legacy name, or counts which class a method lives in is rewritten to the fake-DOM execution harness or rendered-DOM contracts. No test slices JS method bodies or pins selectors/CSS rule text.

Acceptance criteria:
- [ ] All 20261012 keyboard/drag/flip behaviors are unchanged after the split — every route below behaves exactly as today:
  - Pressing the backquote key toggles the debug counters on the player deck/hand, the enemy deck/hand, and each lane; it never types into the page.
  - Arrow keys move keyboard focus between the four regions: from the hand, up goes to the first field card, down to the end-turn button, and left/right select the neighboring hand card; from the field, up goes to the end-turn button, down to the remembered hand card, and left/right move focus to the neighboring field card; from the end-turn button, up goes to the remembered hand card, down to the draw button, and right to the last hand card; from the draw button, up goes to the end-turn button, down to the remembered hand card, and left to the first hand card. Left from the first hand card and right from the last hand card leave the hand toward the draw and end-turn buttons respectively.
  - With a hand card selected and its lane preview showing, all four arrow keys cycle the preview through the four lanes, wrapping around.
  - With a hand card selected and no lane preview, left/right cycle through the playable hand cards, wrapping at both ends, selecting and focusing each card.
  - Typing digits selects that numbered selectable hand card; multi-digit entry works, and an out-of-range number falls back to its last digit.
  - Enter or Space with a selection: on a normal selection it stages the selected card to its previewed lane as a face-down hologram and records the pending play; on a selected ghost it confirms the flip instead; on a card already staged-flipped it just clears the selection.
  - Enter or Space with nothing selected: on the draw button it draws, on the end-turn button it ends the turn, on a focused face-down field card it flips that card, and on a selectable hand card it selects that card.
  - Pressing-and-holding the end-turn or draw letter key until the hold feedback completes activates that action, and releasing early cancels it; the shortcuts stay inactive outside the player's own action phase.
  - Plus and minus step through the playable hand cards forward and backward, wrapping, and held keys keep stepping.
  - Escape, 0, and Backspace cancel the current selection; Escape returns focus to the remembered hand card when it is still selectable; with nothing selected they do nothing.
  - Focusing a played hand card, a selected ghost, or a flipped face-down lane card shows the curved arrow to its hologram; blurring removes it; no duplicate arrows appear.
  - Dragging a hand card onto a lane drops a face-down hologram preview and records the pending play; clicking a face-down lane card or hologram flips it once per render; clicking a hand card selects it the same way the keyboard does; touch drags behave identically.
- [ ] Every other behavior of the script (mouse selection, touch drag, cookie staging, affordance greying, cleanup on destroy) is unchanged.
- [ ] The keydown dispatcher is a data-driven route table: routes are declared as named entries with guards rather than a cascading key-by-key if-chain, and adding or reordering a behavior means editing the table rather than nesting another branch.
- [ ] The _Legacy shim layer is gone: each predicate has one owner and one name across the modules.
- [ ] python3 manage.py test is fully green, and no test slices JS method bodies or pins selectors/CSS rule text — tests assert rendered-DOM contracts and survive renames.

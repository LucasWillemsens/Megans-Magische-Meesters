Make the active challenges list on the player page take less space, show the result when a game is over, and link own active games straight to the board.

Current state:
- `MMM/views.py` `viewPlayer()` builds `challenges` from `BattleParticipant.player.challenges.all()` (BattleHistory objects) and passes them to `MMM/jinja2/MMM/viewPlayer.jinja2`.
- `viewPlayer.jinja2` renders each challenge as a big `.challenge-card` with heading, lootPile line, started timestamp, and a participants list; the whole card links to `{{returnURL}}game/{{challenge.game.get().id}}/{{player.id}}` (the game page, not the board).
- `MMM/models.py`: `BattleHistory` has `challenger`, `participants` (BattleParticipant M2M), `game` reverse relation (`Game.history` FK); `Game.over()` and `MMM/views.py _game_result(game)` can compute finished/winner state.

Implementation:
1. `MMM/views.py` `viewPlayer()`:
   - Replace the plain `challenges` list with a list of enriched dicts (one per challenge): `{history, game, participants, isParticipant, finished, won, boardUrl, gameUrl, started}` where:
     - `game` = the challenge's `Game` (via `challenge.game.first()`), may be None — handle gracefully.
     - `isParticipant` = the viewing player is in `history.participants`.
     - `finished`/`won` via `_game_result(game)` (won from the viewing player's perspective: player in the surviving participants; if not finished, `won` is None).
     - `boardUrl` = `f"/game/{game.id}/board/{player.id}/"` when the player partakes in an active (not finished) game; otherwise fall back to `gameUrl` (`f"/game/{game.id}/{player.id}/"`). Keep the old URL for non-participant/pending challenges and finished games (or link finished own games to board — board redirects to result; choose board for finished own games too and document).
   - Keep query counts reasonable (prefetch participants).
2. `MMM/jinja2/MMM/viewPlayer.jinja2`:
   - Compact challenge rows: single-line-ish layout (title, opponents inline, loot, status) with much less vertical padding; finished games get a small result badge ("Won"/"Lost"/"Fled") in the preview.
   - Use `boardUrl` for own active/finished games so clicking loads the board immediately (board already redirects to result when finished).
   - Keep the whole row a single keyboard-navigable link (tests depend on `challenge-card-link`).
3. `var/www/static/style.css`:
   - Compact `.challenge-list`/`.challenge-card` styles: horizontal/inline participants, smaller padding, `gap` reduced; add `.challenge-card--over`/result badge styles.
4. `MMM/tests.py`:
   - Update `test_challenge_card_is_one_keyboard_link_with_valid_metadata_markup` and related challenge-page tests for the new URLs (own active game links to board URL) and result badge; keep "No participants" and pending-challenge behavior.

Acceptance criteria:
- [ ] Challenge list takes visibly less vertical space.
- [ ] Finished games show their result (won/lost) in the preview row.
- [ ] Clicking an active challenge the user partakes in goes straight to the board (not the game page).
- [ ] Pending challenges (no participants) still link to the game page and show "No participants".
- [ ] Rows remain single links with valid focus/hover styles.

Dependencies: independent of the board leaves; can land anytime, but do it last to avoid test churn.

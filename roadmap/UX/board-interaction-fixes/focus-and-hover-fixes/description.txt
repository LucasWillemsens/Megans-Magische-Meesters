Fix focus behavior for unplayable handcards and the draw button, make cardRow cards focusable, and add a 0.5s hover cooldown driven by mouse movement.

Current state:
- When play allowance is exhausted, hand cardContainers get `.blocked` + `draggable="false"` + title, but the removed-in-earlier-leaf form had focusable buttons; after `handcard-action-merge/`, cards get `tabindex="-1"` — blocked cards must not be reachable/focusable at all.
- The draw button is disabled when draws are exhausted (`viewBoard.jinja2` + `cardDragDrop.js applyTurnAffordances()`), but the deck stack itself can still be visually hovered/focused in odd ways; ensure no focus trap.
- Lane cards (`.cardRow li.cardContainer`) have no tabindex today and cannot receive focus.
- CSS hover rules (`cards.css`, `cardDragDrop.css`) trigger instantly on `:hover`, causing rapid flicker when the pointer crosses cards quickly.

Implementation:
1. Focus for unplayable cards / draw:
   - `var/www/static/cardDragDrop.js`: when `applyTurnAffordances()` blocks cards, remove `tabindex` from blocked hand cards (set `tabindex="-1"` removal via `removeAttribute` or keep `-1` only for playable). Ensure `_isPlayableKeyboardCard` and click-to-select ignore blocked cards (already mostly true — verify).
   - Draw: when draws exhausted, the draw button is `disabled` (already unfocusable); ensure the deck li/stack never receives focus (no tabindex on deck elements). If the user prefers visible indication instead of non-focusability, keep the `title` tooltip — disabled state is the visible indication.
2. cardRow cards focusable:
   - `MMM/jinja2/MMM/battle/viewBoard.jinja2`: add `tabindex="0"` to own-board lane cardContainers (cards row and trustedCards row) so they can receive keyboard focus; keep faceDown flip cards' click behavior; add focus handlers if needed so Enter/Space on a face-down card triggers the flip (reuse `onFaceDownCardClick` via keydown listener) — or at minimum ensure focus is visible and cards are reachable via Tab. Enemy lane cards stay non-focusable.
   - CSS: ensure `:focus-visible`/`:focus-within` lift and outline styling applies to lane cards (already present via `.playingCards ul.cardRow li.cardContainer:focus-within`; verify outline visibility).
3. 0.5s hover cooldown (JS-managed hover):
   - `var/www/static/cardDragDrop.js` (or a small new module loaded in `viewBoard.jinja2`): replace CSS-only hover-triggered selection of "hovered card" with a JS hover manager:
     - Track `mousemove` on the player board/hand/lane areas; only update the hovered card when the mouse actually moves.
     - Apply the hovered state via a class (e.g. `.card-hover`) instead of relying solely on `:hover`, with a 0.5s cooldown between switching from one card to another (a timer; switching to a new card is only allowed after 500ms since the last switch, unless the pointer leaves all cards, which may clear immediately).
     - This governs the visual hover effects (lift/rotation/fade) for hand cards, lane cards, and holograms.
   - CSS: add `.card-hover` equivalents for the existing `:hover` visual rules (hand card morph/raise, lane card lift, hologram lift); keep `:focus-within` as-is. Keep `:hover` for non-card UI elements (buttons, links) unchanged.
   - Ensure drag-and-drop and click-to-select are unaffected (the hover manager must not swallow clicks/dragstart).

The deck stack must not visually move when the top card is drawn.

Current state: `var/www/static/loadingAnimations.js` `duplicateCard()` for negative source lanes (`sourceLane < 0`, i.e. deck origin) inserts the clone into the active deck `<ul class="deck">` at `insertIndex = min(max(0, ordinal - 1), children.length)` — ordinal for deck cards is 0 or low, so the clone is inserted as the first child, shifting all absolutely-positioned `nth-child` deck card `li` elements by one slot (CSS `ul.deck li:nth-child(n) { left/bottom }` offsets change). This makes the whole deck stack jump when a draw animation runs.

Implementation:
1. `var/www/static/loadingAnimations.js` `duplicateCard()`:
   - For `sourceLane < 0` (both player and enemy), do NOT insert the clone into the deck ul. Instead position the clone absolutely at the deck's top-card location (compute from the deck element's bounding rect / last card li) using the same fixed/absolute translate technique used elsewhere (`--move-x`/`--move-y` to the original element's rect, `position: fixed` or absolute within a positioned ancestor, `.duplicate` class with `to-original` transition).
   - Ensure the clone is appended to a neutral container (e.g. `document.body` with fixed coords, or the `.deckHand`) so inserting it does not change the deck's `nth-child` layout.
   - Keep the face-down back styling for the draw clone.
2. Verify `_flyCardToDeck()` and `_wiggleDeck()` remain consistent (they already use `activeDeckForBoard()` and rect math — reuse the pattern).
3. `MMM/tests.py`: add/adjust a static contract test asserting the draw (negative source lane) path does not `insertBefore`/`appendChild` into the deck ul and uses rect-based positioning.

Acceptance criteria:
- [ ] During a draw animation, the deck stack's position/size does not change; only the flying card clone moves.
- [ ] The draw clone still starts at the deck's top card and lands on the drawn hand card.
- [ ] Enemy deck draw animations behave the same.
- [ ] No layout shift of the deck on draw.

Dependencies: after `deck-indicator-restyle/` (deck geometry changes) and `keyboard-selection-extensions/` (animation sequence stability).
